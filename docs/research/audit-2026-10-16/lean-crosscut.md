1. **Path folding is written ~17 times with two different lower-casing rules** (`crates/nif/src/path.rs:42-48`, `crates/engine/src/group.rs:193-195`, `crates/engine/src/sets.rs:44-49`, `crates/engine/src/manifest.rs:288-294`, `crates/engine/src/grass.rs:49-55`, `crates/engine/src/overrides.rs:95`, `crates/gui/src/model/input_name.rs:21-23`, `crates/gui/src/model/rename.rs:182-184`, `crates/gui/src/model/pbr_export.rs:394-396`, `crates/gui/src/model/export.rs:85-87,296-303`, plus 64 inline sites)
   - **What this is:** "Normalise a path" (turn `\` into `/`, lower-case, sometimes trim a leading `/` or the extension) so two spellings of one Windows path compare equal. Each crate, and most GUI modules, wrote its own.
   - **Problem:** Count: 17 named helpers (`slashes_lower`, `fold`, `fold_id`, `normalize_key`, `path_key`, `lower`×3, `path_lower`, `slash`×5, `norm`×3, `canon`, `backslash`) and 64 inline `.replace('\\', "/")` calls, 22 of which also lower-case. They already disagree: `nif::path::slashes_lower`, `engine::grass::path_key`, `engine::discover` (game paths), `modscan/store.rs:297` and `render3d/locate.rs:43` use `to_ascii_lowercase()`; `engine::group::fold`, `engine::sets::fold_id`, `engine::manifest::normalize_key`, `engine::overrides::KeyForms::of` and every GUI copy use Unicode `to_lowercase()`. For a mod folder `Ärger\rock_n.png` the game-path world keys it `textures/Ärger/rock_n` while the set-key world keys it `textures/ärger/rock_n`: two helpers that both document themselves as "the lower-cased path" return different strings for the same file. Today the two worlds are compared only through functions on the same side (traced `gras_diffuses` producer `gui/model/meshes.rs:365` → consumer `engine/api.rs:1063`, `fold_id` callers, `canon` callers), so this is drift waiting for the first cross-comparison, not a live bug.
   - **Fix:** Two helpers, both public: `nif::path::slashes_lower` (game paths: ASCII, trims leading `/`) and `engine::group::fold` made `pub` (project/set keys: Unicode). Delete the three GUI `lower`/`path_lower` copies and `export.rs::slash` (they are byte-for-byte `fold`), and replace the 22 inline lower-casing sites with `fold(..)`. Pick one lower-casing (ASCII, since Windows file systems fold ASCII only and nif/modscan already chose it) and write it once in `fold`; `engine/tests/set_edits.rs:93` (`"/Äpfel/Stein/"` → `"äpfel/stein"`) is the one test that pins the Unicode behaviour and would change.
   - **If we skip it:** The next feature that joins a scan-DB path to a set key (the PBR-grass work already carries both in `BatchRequest`) silently misses every non-ASCII folder.
   - **Group:** Should fix. **Kind:** lean.
   - **Confidence:** high on the count and the ASCII/Unicode split (grepped every `replace('\\'` and `to_ascii_lowercase|to_lowercase` site); medium that no cross-comparison exists yet (traced the three key producers named above, not all 64 sites).
