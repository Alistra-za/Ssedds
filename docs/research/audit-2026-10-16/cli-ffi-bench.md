# Audit: crates/cli, crates/encoders-sys (FFI + vendor), crates/bench, engine test shim, tools, workspace manifests

Scope read in full: `crates/cli/src/{main,args,verbs,human,cancel}.rs`, all 9 CLI test files (names + the exit-code, JSON, cancel and panic tests in detail), `crates/encoders-sys/{build.rs,src/*,shim/sdc_shim.cpp,tests/*}`, `vendor/SHA256SUMS`, `README-VENDOR.md`, the bc7e patch, the ISPC headers, the relevant ISPC kernel entry points (`bc7e_compress_blocks`, `CompressBlocksBC6H_ispc`, `load_block_interleaved_16bit`, `store_data`), `tools/*.ps1`, `tools/gen-cs-pbr-templates.py`, `crates/engine/src/bin/nvcompress.rs`, `crates/bench/{Cargo.toml,src/main.rs,src/lib.rs,src/corpus.rs,tests/*}`, every `Cargo.toml`, `Cargo.lock` (duplicate-version scan), `rust-toolchain.toml`, `.cargo/config.toml`, `.gitattributes`.

## Findings

1. **Every report verb panics on a closed stdout and exits 3 (fatal)** (`crates/cli/src/verbs.rs:132-170, 214-305, 401, 657, 743, 792-816, 854, 906-921, 939, 948-951, 962-982, 1029-1064, 1132-1158` — 51 `println!` and 2 `print!` sites; `crates/cli/src/main.rs:77-86`)
   - **What this is:** `inspect`, `validate`, `presets`, `encoders` and `patch-header` write their report with `println!`. Rust's `println!` panics when the write fails ("failed printing to stdout"); a reader that stops early closes the pipe, so the next write fails with BrokenPipe. The engine's `JsonLinesSink` (`engine/src/events.rs:204-215`) already drops write errors on purpose; the verbs' own lines do not.
   - **Problem:** `sdc validate *.dds --json | Select-Object -First 1` (or `| head -n1`, `| more` then `q`): after the first line the next `println!` panics, `main`'s `catch_unwind` prints `sdc: internal error` and returns **exit 3**, the code reserved for fatal failures. A script checking `$LASTEXITCODE` treats a healthy validate run as a crash. The same happens to `inspect --json` on a folder of a few thousand DDS when the consumer stops reading. (`docs/AUDIT-2026-10-14.md` item 11 already lists this; it is still unfixed in the code.)
   - **Fix:** One stdout writer: change `say()` (`verbs.rs:590-596`) to `let _ = writeln!(std::io::stdout().lock(), "{line}")` / `let _ = writeln!(std::io::stderr(), ...)`, add a tiny `out!` macro (`macro_rules! out { ($($t:tt)*) => { let _ = writeln!(std::io::stdout().lock(), $($t)*); } }`) and replace every `println!`/`print!` in `verbs.rs` with it. No new state.
   - **Missing test:** none of the 4,300 test lines closes stdout. Add one in `cli_inspect_validate.rs`: spawn `sdc validate a.dds b.dds --json` with `Stdio::piped()`, drop the child's stdout handle before `wait()`, assert exit 0/4, not 3.
   - **If we skip it:** Every pipeline that pipes `sdc` into a pager or `head` gets the fatal exit code; CI scripts around `sdc validate --json | jq -e ... ` misreport.
   - **Group:** Must fix. **Kind:** bug (+ missing test).
   - **Confidence:** high — counted the sites, traced `main.rs` `catch_unwind` → `ExitCode::from(3)`; `JsonLinesSink` and `human.rs` are the only writers that already ignore errors.

2. **`presets export --out` overwrites the target file non-atomically** (`crates/cli/src/verbs.rs:936-939`)
   - **What this is:** The export writes the preset text with `std::fs::write(&p, &text)` straight onto the destination. Everything else the project writes to disk goes through `engine::dds::write_atomic` (temp file in the same folder, then rename).
   - **Problem:** `sdc presets export cs --out D:\mods\presets\mine.toml` onto an existing file that is *not* a loaded preset (the refusal at `:930-935` only covers loaded presets) with a full disk or a kill mid-write: `fs::write` truncates first, so the old `mine.toml` is gone and a 0-byte or half file is left. The user's hand-edited preset is lost.
   - **Fix:** `Some(p) => engine::dds::write_atomic(&p, text.as_bytes())` — one line, the helper already exists and is in scope (`engine::dds` is imported).
   - **If we skip it:** Rare but unrecoverable: the one file type users hand-edit can be destroyed by the tool that is meant to help write it.
   - **Group:** Nice to have. **Kind:** risk.
   - **Confidence:** high — `write_atomic` signature read (`engine/src/dds.rs:353`), `loaded_from` only knows presets loaded from `%APPDATA%\sdc\presets` and `--preset-file`.

3. **Two TOML stacks in the lock file; the workspace `toml = "0.8"` is the odd one out** (`Cargo.toml:17`, `crates/gui/Cargo.toml:26` (`toml_edit = "0.25"`), `Cargo.lock`: `toml 0.8.23` + `toml 1.1.8`, `toml_edit 0.22.27` + `0.25.17`, `toml_datetime 0.6.11` + `1.1.2`, `serde_spanned 0.6.9` + `1.1.2`, `winnow 0.7.15` + `1.0.4`, `toml_write 0.1.2`)
   - **What this is:** `engine` and `gui` parse TOML with `toml 0.8`, which drags in the old `toml_edit 0.22 / winnow 0.7 / toml_datetime 0.6 / serde_spanned 0.6 / toml_write` chain. The GUI's in-place preset editor uses `toml_edit 0.25` (new chain: `toml_parser`, `winnow 1`, `toml_datetime 1`, `serde_spanned 1`), and `egui_kittest` already pulls `toml 1.1.8`. So the same parser is compiled twice in two generations.
   - **Problem:** Six redundant crates in every build (`toml 0.8.23`, `toml_edit 0.22.27`, `toml_datetime 0.6.11`, `serde_spanned 0.6.9`, `winnow 0.7.15`, `toml_write 0.1.2`), two TOML grammars in the shipped exes, and two places to patch for a parser bug.
   - **Fix:** `toml = "1"` in `[workspace.dependencies]`. The API used (`toml::Table`, `toml::Value`, `toml::from_str`, `toml::to_string`, `toml::to_string_pretty`, `toml::de::Error`, `Value::as_table/as_array/as_str`, `Value::deserialize`) is unchanged in toml 1.x; `parse_value`'s `v = {raw}` trick (`engine/src/overrides.rs:288-293`) keeps working. Run `cargo update -p toml` and the engine/gui preset tests.
   - **If we skip it:** Nothing breaks; the build stays ~6 crates and a few seconds heavier for good, and the lock keeps carrying two versions of the parser forever.
   - **Group:** Nice to have. **Kind:** lean.
   - **Confidence:** medium — API surface grepped (20 distinct `toml::` items, all present in toml 1.x); cannot run cargo here to prove the bump compiles.

## Checked and clean (the brief's specific questions)

- **FFI preconditions (11 unsafe sites):** every wrapper asserts the buffer lengths the C side reads/writes before the call: `bc7e_compress_blocks` (`pixels.len() % 16`, `out.len() == n*16`), `bc6h_compress_rows` (`width>0`, `width%4`, `rows%4`, `rgba_f16.len()==w*r`, `out.len()==(w/4)*(r/4)*16`), rgbcx wrappers (fixed 64-byte in / 8- or 16-byte out arrays, `level <= 18`, `channel < 4`; `search_radius` is clamped to 0..=255 inside `encode_bc4_hq`). Enum discriminants index `g_bc7[7]`/`g_bc6[5]` in the shim without a range check, and all three enums are closed with matching counts.
- **Alignment:** bc7e gets a fresh `Vec<u32>`/`Vec<u64>` (natural alignment for the ISPC uniform pointers). The BC6H kernel reads the half-float rows with 4-byte *gathers* at byte offsets +0/+2/+4 inside each 8-byte texel (`kernel.ispc:150-167`), so the 2-byte-aligned `[[u16;4]]` slice is fine and the last gather ends exactly at the slice end. `store_data` writes `width/4 * 16` bytes per block row, matching the engine's per-band `o` (`engine/src/encode.rs:286-293`).
- **Tail blocks:** `bc7e_compress_blocks` uses `foreach (block_index = 0 ... num_blocks)` (`bc7e.ispc:4707`), so lanes past `n` are masked, no over-read for `n % programCount != 0`.
- **Thread safety / init:** `rgbcx::init` and `bc7e_compress_block_init` run once under `OnceLock`; `g_bc7`/`g_bc6` are written only there; all encode entry points are called after the lock is initialised (`ensure_init`). The decode path passes the BC1 model per call, so the only process-global state is the encoder's model, which `init()` guards with `ModelMismatch`. Traced the plan path of `sdc convert`: `load.rs:248` and `dds_patch.rs:132` decode with `None` (bcdec), so nothing pins Ideal before `api.rs:1726` calls `init(req.bc1_model)`.
- **CPU without AVX2:** `bc7e.obj`/`kernel.obj` are ISPC multi-target dispatchers (`__get_system_best_isa`, `*_sse2/_sse4/_avx/_avx2` variants, `__terminate_now` only below SSE2). `manifest::dispatched_isa` mirrors ISPC's rule (avx2 needs FMA+F16C; sse4 means SSE4.2).
- **build.rs:** fails loudly: missing header → `expect`, missing `.obj` → `lib.exe` error, non-Windows without `SDC_LINUX_OBJS` → `expect`. The patched/unpatched detection (header text) is checked at runtime by `tests/bc7.rs::exact_opaque_decodes_alpha_exactly_255_where_upstream_gives_254`, and `vendor_manifest.rs` pins every vendored byte (SHA256SUMS has CRLF endings; `str::lines()` strips them, `.gitattributes` keeps `vendor/** -text`).
- **CLI exit codes:** `convert` 0/1/4 from `BatchSummary::exit_code`, 2/3 from `EngineError`; `inspect` 1 on unreadable/plan-failed; `validate` 1 > 4 > 0; `presets validate` 1; `patch-header` 1 per refused/failed file (its doc comment still says a write failure is exit 3 and stops — stale, code is right). Tests cover each.
- **Ctrl-C:** first interrupt sets the flag only; bands check it; outputs go through `write_atomic`; second interrupt `process::exit(3)`. Leftover `.sdc-*.tmp` after the second Ctrl-C is a documented decision (`DECISIONS.md:237`, `cancel.rs:11-15`).
- **Paths:** trailing slashes are harmless (`walkdir` + component-wise `strip_prefix`, `Path::file_name` ignores them); `\\?\` prefixes flow through `game_path`'s component lowering and `strip_root`'s `\`→`/` rewrite.
- **`--set`:** `split_once('=')` keeps `=` in values; an empty value becomes the string `""` and fails typed validation downstream; `subtype`, `reencode`, `rnm.target` and unknown fields are rejected at parse time; 40 distinct `parse_set` inputs are exercised by engine tests.
- **bench:** alive, not dead weight. All nine `engine::` APIs it uses exist; every corpus test self-skips without `SDC_BENCH_ROOT`; `README-VENDOR.md` names its `exact-opaque-native` gate as the patch's bit-identity proof. It is single-machine (default root `F:\ai\dds\bench`) and the only user of `anyhow`.
- **Dependencies:** every `[dependencies]` entry of every crate is referenced in its `src/`; no feature flags are declared beyond `test-hooks`/`serde`.

Smaller findings left out: 11 (stale `patch_header` doc comment; `vendor_manifest` asserts `n >= 22` for 24 files and cannot notice an *unlisted* new vendor file; `nvcompress` test shim's `(by*4*w+bx*4)*4` overflows `u32` at 16k² inputs; `inspect`'s `sdc-inspect-*` temp dir survives a hard Ctrl-C; `bc7e_compress_blocks` allocates two Vecs per band; three no-op duplicate dev-dependency lines — `cli` `serde_json`, `vfs` `lz4_flex`, `gui` `image`; `human.rs` prints `Stage` as Debug (`Encode`) where JSON says `encode`; `cargo test -p sdc` compiles the whole GUI stack for one parity test (`gui_repro.rs`); a `file:<glob>` containing `=` gives a misleading `--set` error; `strip_root` compares a lowercased char-count prefix (breaks only for case-changing multibyte letters in the temp path); `inspect` has no Ctrl-C handler, so a long inspect dies with the default exit rather than listing pending files).

Not read: `crates/bench/src/{gates,engine_gates,s7,s7b,radius,codec,metrics,ddsraw}.rs` bodies (only their imports and entry points), `crates/bench/examples/bc45_decoder_probe.rs`, the bodies of `vendor/bc7enc_rdo/rgbcx.{h,cpp}` beyond the patched `get_block_values` and the `encode_bc4_hq` radius clamp, `vendor/ispctc/ispc_texcomp.cpp` beyond `CompressBlocksBC6H`, the ETC/BC7 parts of `kernel.ispc`, the CLI test bodies other than `cli_basics.rs:41-125`, `cli_edges.rs:114-152, 425-448`, `gui_repro.rs`, `static_crt.rs`.

Lean: ~6 lock-file crates (the toml 0.8 chain) and 3 manifest lines; no source worth deleting in this scope. `crates/cli/tests` dev-dep on `sdc-gui` is the single biggest test-build cost but is doing a real job.
