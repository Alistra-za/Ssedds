# M5: NVTT Production backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** draft for owner review (2026-10-13). Tasks 2 onward are written for the case where Spike S7b (Task 1) passes;
each says what changes if it does not.

**Goal:**
- `encoder.backend = "nvtt"` encodes BC7 and BC6H with the user's own `nvcompress` (Production), one process per level.
- NVTT is found from an explicit path, then `PATH`, then the default install folder, and its version is checked.
- `ENC-NVTT-MISSING` and `ENC-NVTT-VERSION` mean what the spec says; a failed run is `ENC-NVTT-FAILED` on that file.
- `sdc convert --nvtt` works; `sdc encoders` reports the version; the GUI has an NVTT path and an Encoder row.

**Architecture:**
- A new engine module `crates/engine/src/nvtt.rs` owns everything NVTT: `locate`, `probe`, `NvttTool`, the batch-wide
  process slot, and `encode_level_nvtt`.
- `pipeline::encode_levels` dispatches: `Backend::Nvtt` → `nvtt::encode_level_nvtt`, else the unchanged `encode::encode_level`.
- The encoder-independent BC7 post steps in `encode.rs` (rotated opaque fix, grass corner guard) move into one
  `pub(crate) fn bc7_post_fix` used by both paths. Built-in output stays byte-identical (golden test unchanged).
- The probe runs once per batch (`Engine::plan` and `Engine::run`) and reaches `check_profile` through `ResolveCtx`.
- Tests that need no NVTT use a fake `nvcompress` (a test-only binary in a new workspace crate `crates/nvtt-fake`). Tests
  against the real NVTT 3.2.5 are `#[ignore]` and run on the owner's machine.

**Tech Stack:** Rust 2021 workspace (rust-version 1.88; no let-chains), Windows MSVC only. `engine`, `cli`, `gui`, `bench`.
`std::process::Command` only; no new external crates.

**Spec:** `docs/superpowers/specs/2026-10-13-sdc-m5-nvtt-design.md` (draft, §9 open questions). Parent design spec §7.5.

### Plan rulings (Note NV, written by Task 9)

- **NV1 Scope.** BC7 and BC6H UF16 only, Production only, one `-nomips` process per engine-built level. NVTT is never a
  default and never suggested.
- **NV2 Locate.** Explicit path (missing → not found, no fallback), else `nvcompress.exe` on `PATH`, else
  `C:\Program Files\NVIDIA Corporation\NVIDIA Texture Tools\nvcompress.exe`.
- **NV3 Version.** Parsed from the no-argument banner `NVIDIA Texture Tools <x.y.z>`; tested = `3.2.5`. Untested →
  `ENC-NVTT-VERSION` (blocking, allowable). Not found or probe failed → `ENC-NVTT-MISSING` (blocking).
- **NV4 Flags.** `-silent -nomips -production`, `-bc7` or `-bc6`, `-noalpha` when `alpha.policy = remove`, `-nocuda` for BC7
  always and for BC6H per S7b. No colour flags; the engine writes the header.
- **NV5 Feed.** Each level is written by `dds::dds_bytes` as `rgba8` (BC7) or `rgba16f` (BC6H) into a per-file temp folder.
- **NV6 Post.** `force_opaque_rotated` and the complex-grass guard run on NVTT BC7 output; the mode-6 byte patch does not.
- **NV7 Slot.** One NVTT process at a time per process (a static mutex). Shortcut: fixed at 1; make it a setting if cores idle.
- **NV8 Failure.** `ENC-NVTT-FAILED` (error, Compress) with exit status and stderr tail; no fallback to the built-in encoder.
  Cancel kills the child.
- **NV9 Preview.** Previews of an NVTT texture encode with the built-in backend for the format and say so (spec §9.1, owner
  to confirm).
- **NV10 Records.** `EncoderVersions.nvtt = Some("3.2.5")` on NVTT records only; `if-changed` re-encodes when it differs
  from the probed version.
