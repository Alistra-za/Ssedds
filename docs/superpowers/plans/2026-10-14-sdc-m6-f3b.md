# M6 Track F3b: input alias, output rename and auto PGPatcher rename (implementation plan)

> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Fix a badly named source without touching it: an `[inputs]` alias in `sdc.toml` that the engine (CLI and GUI) reads.
- Rename a set's outputs: `output_name` in `sdc-project.toml`, or the PGPatcher `rename` key on a CS PBR set.
- One rename dialog (Inputs / Outputs) with find/replace, regex, prefix, suffix, case, a live preview and collision checks, opened from the F3a right-click menus and F2.
- Every Apply is one undo step and one plan.

**Spec:** `docs/superpowers/specs/2026-10-13-sdc-m6-f3b-design.md` (from `…-f3b-decisions.md`, D1-D8).

## Task 1: Engine reads `[inputs]` aliases

**Files:** `crates/engine/src/presets.rs`, `discover.rs`, `overrides.rs`, `api.rs`, `codes.rs`, `schemas.rs` (if the generated schema needs a hand), `schema/config.schema.json`, tests in `crates/engine/tests/discover_group.rs` (or a new `read_as.rs`).

- [ ] `ConfigFile.inputs: BTreeMap<String, ReadAs>`, `ReadAs { #[serde(rename = "as")] path: String }`, `deny_unknown_fields`, skipped when empty. The user config refuses it like `[files]` ("[inputs] is only valid in a project sdc.toml").
- [ ] `InputFile.real_rel: Option<PathBuf>` (`skip_serializing_if = "Option::is_none"`); every constructor sets `None`.
- [ ] `discover::apply_read_as(files, root, output_root, inputs) -> Vec<Warning>`:
  - match each file by `overrides::project_rel(root, f)` + `path_key_matches(key, rel)`;
  - normalise the alias (`\` → `/`, trim), add the real extension when it has none, refuse a different extension, an absolute path, `..`, an empty name;
  - the new `rel` is `<root>/<alias>` relative to the file's discovery folder (`path` minus `rel`); outside it is refused ("outside the input folder");
  - refuse an alias equal (case-insensitive) to another file's real or new `rel`;
  - on success: `real_rel = Some(old rel)`, `rel = new`, `game_path = game_path(abs alias, new rel)`, `output = output_root/new rel .dds`;
  - a refused alias leaves the file as it is and returns an `IN-ALIAS-INVALID` warning naming the key and the reason (spec §9 adjustment: Warning, not per-file Blocking — the GUI dialog never writes an invalid alias, so this only meets hand edits);
  - a key that matched no file returns `IN-ALIAS-STALE` (Info) naming it.
- [ ] `project_rel` takes the real file name when `real_rel` is `Some`, so `[files]`, set edits and `OutputKey::File` stay keyed by the real file.
- [ ] `plan` calls it right after `discover_reporting`, before `canonicalise_outputs`, using `project_root(&req)` and `project_config.inputs`; emits the warnings batch-level like `SET-EDIT-STALE`. The planning-sequence comment gets "1a. `[inputs]` aliases".
- [ ] Codes `InAliasInvalid = "IN-ALIAS-INVALID" => Warning`, `InAliasStale = "IN-ALIAS-STALE" => Info`; the module doc lists them; the count test goes 87 → 89.
- [ ] Regenerate `schema/config.schema.json` (`sdc presets schema all --out schema`, or the schema generator under test on Linux) and `schema/event.schema.json` if codes are listed there.
- [ ] Tests:
  - `wall.png` aliased to `wall_n.png` joins the `wall` set as a normal: rel, game_path, output `wall_n.dds`, `real_rel`;
  - key with and without extension, case-insensitive;
  - folder alias (`a/x.png` → `b/x.png`) moves output and game path;
  - a `[files]` entry keyed by the real path still applies to the aliased file;
  - invalid: other extension, `..`, absolute, collision with a real file, collision between two aliases;
  - stale key;
  - no `[inputs]`: `apply_read_as` changes nothing (and goldens stay green on Windows).
- [ ] Commit: `feat(engine): [inputs] aliases read a source under another name (F3b Task 1)`.

## Task 2: GUI output names and the auto PGPatcher rename

**Files:** `crates/gui/src/sets_doc.rs`, `crates/gui/src/model/sets.rs`, tests in the gui test style.

- [ ] `SetEntry.output_name: Option<String>`; reserved key `output_name`; `SetsDoc::set_output_name(id, Option<&str>)` (writes or removes, respects read-only like `set_lock`).
- [ ] `engine_inputs`: for each set with an `output_name`, on every target, explicit paths for its members: `<member's output dir>/<output_name><canonical suffix>.dds` (`OutputKey::File(item.key)`), and `OutputKey::Packed{set, suffix}` for packed outputs. Then the CS-only PBR candidates as today (a PBR set's prefix wins; it never stores `output_name`).
- [ ] `AppModel::set_output_name(set_id, Option<String>)`: a CS PBR set writes the JSON `rename` key via `set_json_value`; any other set writes `output_name`; both re-plan; one undo step.

- [ ] `AppModel::mesh_refs_to(game_path) -> usize` from the scan database (0 when not loaded).
- [ ] Tests: output_name → `output_paths` on cs, cpm and vanilla; packed member renamed; PBR set → `rename` key written and output prefix follows; clearing restores mirrored outputs; undo.
- [ ] Commit: `feat(gui): output names per set; PBR sets rename through PGPatcher rename (F3b Task 2)`.
