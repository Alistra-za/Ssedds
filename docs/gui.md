# Tessalith user guide (M3a, M3b)

`tessalith.exe` is Tessalith, the graphical front end of the Skyrim DDS converter (the command line is `sdc`). It runs the same engine as `sdc convert`, so a folder you decide and export here converts to the same files from the command line. This guide covers the converter GUI (M3a) and the set editor with the PGPatcher JSON (M3b); texture edits (M3c) come later.

## Sets and the PGPatcher JSON

The **Sets** column is editable. It changes which textures belong to which material set, and it can write the PGPatcher JSON that tells PGPatcher how to use each PBR set.

Moved to [Sets column](wiki/GUI-Sets-Column.md#editing-sets).

### The set editor

Select a set to edit it. The editor is one column that scrolls as a whole, like a texture's settings: the input name box at the top, then the slot rows at full width, then two tabs, **Material** (**Set** on a vanilla set), which holds the material settings, and **Advanced**, the last tab, which holds the same sections as the Advanced drawer. Nothing sits beside the slot rows, so nothing covers them at any window width. A card wider than the centre is cut at the window edge (it does not scroll sideways). The window-edge drawer is not drawn while the tabs are shown; in 3D, with a texture selected, or with several sets selected, the tabs are not shown and the drawer is. Each PGPatcher slot is one row in a table, in slot order, so there are at most 8: Diffuse, Normal, Emissive (or Skin _sk), Height, RMAOS, **Coat normal / Fuzz (slot 7)**, Subsurface. Slot 7's card holds the set's `_cnr` or `_f`, whichever it has; with both, the card shows the conflict in red (PGPatcher has one slot 7), lists both files with a ✕ each to take one out of the set, and export warns "_cnr and _f both use slot 7". Its slot commands, file drop and PGPatcher lock (`lock_cnr`) are slot 7's. (Note AO) Only the slots the set's shader can use are shown. A filled slot the shader cannot use stays, with an amber outline, and its title says why on hover. A card has a **preset dropdown** (it fills the PGPatcher settings for that kind of material), and **Slot commands** to move, share, duplicate or clear the slot. **Opaque** sits on the Diffuse card. A complex material `_m` (packed or loose) has no card; its **Enable parallax** box sits under the cards, with a packed `_m`'s fill rows. The Diffuse and Normal cards have **Match on this** (see Matching below). A `_coat` map fills the Subsurface card, which then reads **Coat colour + strength**: its alpha is the coat strength and is kept.

**Slot rows.** A row has these columns: *Slot* (the title; weak when the slot is empty; a lock when pinned), the *thumbnail* (click selects, double-click expands; the PGPatcher lock padlock and hover are on it), *File* (the name cut to fit, with the full name and size on hover, and under it the dimensions and file size), *Format* (the format dropdown; an empty slot shows **Assign...** here, which opens the slot menu, headed by the slot's name such as "Emissive / Skin (slot 3)"; a packed output's recipe and fills sit under the dropdown), *Flags* (small toggles: Match on this, Opaque, each with a hover) and *Status* (a dot: green ready, amber a warning or decision, red blocks; its hover gives the reason, such as "borrowed from X", "not used by the shader" or "RNM, 2 layers"). The File column takes the width the other columns leave, so the rows fill the centre. While a set is selected the Textures and Sets columns give the centre at least 540 px, down to their own minimums, so the rows fit without clipping from a 1024 px window up (the Sets column is at its narrowest there). Right-click on a row opens the slot menu. Everything the cards did (PGPatcher padlock, RNM outline, clash rows, Match on this, borrowed, Opaque, packed controls, slot menu, Explorer drop, the click/double-click wait) is kept.

**Packed channel sources.** Under a packed output's format dropdown (`_rmaos`, `_rfaos`, `_m`, `_p`), each channel row is the channel's role (for example *AO*), then a **Source** picker, a combo that reads **Source: <file>** or **Source: value** (it is as narrow as the format combo, so a long name is cut; hover shows it whole). The list holds the set's greyscale helpers (any role but the RNM layers) and **Value**:
- Picking a helper makes it this channel's source: the channel is added to that helper's `helper.fills` and taken out of every other helper's list, as one undo step. The helper panel's Fills list shows the same setting (one store, two views).
- **Value** takes the channel out of every helper's list, so the channel uses its value fill: the row then shows the value box and its Reset after the picker, as before (`packing.fill.*`). Value is greyed out when the channel's file is not a helper ("<file> is not a helper; it feeds this channel by its name"), because no helper setting holds it.
- Picking the source already shown changes nothing. The engine still decides: a pick that cannot fill the channel shows the helper as not used, with the reason, in its row and panel.

**Drop files from Explorer on a row.** A file dropped on a slot row fills that slot, as one undo step, when it is a texture of the open folder and its sub-type belongs in that slot. It moves in the way a texture dragged from the Textures column does: a filled slot asks **Replace** or **Cancel**, a pinned slot refuses, and Share or Duplicate are not offered, so nothing is copied. A file outside the open folder is not copied either: the line under the rows says "brick.png is outside the open folder; files are never copied". Drop several files and only the first is used ("only the first file was used"). A file dropped anywhere else opens its folder, as before. A slot row whose texture just changed (a drop, **Replace**, **Assign…**, a file from Explorer, undo or redo) outlines in the accent colour for about a third of a second, then fades; only the first changed slot flashes, and a slot that only emptied does not. Two slot kinds share a number (Emissive and Skin 3, Coat normal and Fuzz 7), so with both filled a change to one of them may not flash. While the pointer is down on a slot's thumbnail it shrinks slightly (3%).

**Path pickers.** The ▾ beside the input name box in the set's header row, and the ▾ beside a match path or a mesh path in the JSON editor, open a list of known paths with a filter box. Clicking or typing inside it (the box, the list, its scroll bar) keeps it open; it closes on a pick, on Esc, or on a click outside.

**Input name box.** The set's header row shows its input name (the box alone names the set; there is no separate heading) (the path its textures are read as) in a text box. Typing shows the best known texture path in gray after the text; Tab takes it up to the next `/` (again to keep going), Right arrow at the end takes all of it. A list of up to 12 matching known paths shows under the box as you type (the bold top row is the gray completion): Up/Down highlight a row, Enter applies the highlighted row (or the typed text when none is), and a click applies that row. The first Esc closes the list; Esc again puts the old name back. Enter or clicking away applies a valid new name as one undo step; Esc, or clicking away from an invalid or unchanged name, puts the old one back. An invalid name has a red outline and the reason on hover. The folder part is locked (dimmed, read-only): the rail along the box's lower edge has a stop at each `/`, and dragging the rail or its teal lock icon (the "Path lock" handle, on the track under the text), or Ctrl+Left/Right in the box, locks more or less. The ▾ shows all known paths under the locked part, with a filter box, for browsing. Paths under `textures\pbr\` are PGPatcher's outputs and are never offered. The lock lasts for the session and is not saved. (Note AO)

**Match selector (TruePBR JSON sets).** In the 2D view, the **Match** box beside the input name box (**Match 1** to **Match 8**; its list names each slot) picks the slot the ▾ list works on. Slot 1 is the input name list above: a pick renames the set's textures. Slots 2–8 list the textures the scan saw in that slot, and a pick sets that slot's match in the PGPatcher JSON (`match2`…`match8`); the set's files keep their names. **All slots** in the list shows every known texture; a pick goes to the selected match, and the selector never moves by itself. It starts at the set's lowest unused match (Match 2 for a set whose only match is its own diffuse), or at the match you last chose for that set, which `gui.toml` keeps per project and set (Note FC12). In a project with no `textures` folder in its path, the set names and the offered paths both leave out `textures/`. (Note DO)

The set's **Shader** dropdown lists the shaders the current mode offers. The picked one reads "(auto)" when Tessalith chose it, and "(fallback)" when the shader you asked for does not exist under the current mode and `default` stands in. Choosing **Auto** clears your choice. Warnings (a missing or unused map, an unavailable shader) show on the set's ⚠ badge. A scanned mod's meshes decide the auto pick unless a PBR or skin member, a complex `_m` or a `_p` does.

### PGPatcher settings

- Features that cannot go together are **greyed**, with the reason on hover: hair excludes multilayer, glint, fuzz, emissive, parallax and subsurface; multilayer excludes subsurface; multilayer, glint and fuzz exclude each other; fuzz and coat normal exclude each other, because they share one slot. A switch that is already on stays enabled so you can turn it off.
- **Groups.** The material settings are framed groups in this order: Material, Features, Coat, Subsurface, Emissive, Parallax, Glint, Fuzz, NiAlphaProperty, Matching, CS PBR records, Advanced TruePBR settings. A header shows the group title and, right-aligned, its value: Subsurface Off / Standard / Foliage, Coat / Emissive / Parallax / Glint / Fuzz "on" or "off", NiAlphaProperty "set" or "off", Matching "2 matches" or an amber "matches nothing", CS PBR records "N records". The feature groups are always listed; while the feature is off they read "off" and are closed, and one opens when its feature turns on. NiAlphaProperty and Advanced TruePBR settings start closed. Click a title to open or close it. A feature's state shows once, in its own group's header; the Features group (the ticks) has no value. A feature that is on but blocked (multilayer with hair) reads "on, blocked by hair" (amber) in its own header, stays closed and stays ticked in Features (Note FC9).
- **Readable labels.** Skin and complex-material keys show plain names ("SSS width", "Fuzz F0"); hover one for its exact key.
- **Coat** (was "Coat settings") sits under the **Multilayer (coat)** checkbox: coat colour (with the colour field), specular level, roughness, strength, diffuse, normal, parallax and inner UV scale. Multilayer is what makes them take effect. With Multilayer off the group reads "off" and stays closed, the values are kept but not written, and a note says how many are kept. Inner UV scale only shows where the diffuse alpha is below 1 and the set has an inner-layer texture.
- **Switches turn on by themselves from the set's textures**: a `_cnr` turns on Multilayer and Coat normal, an `_f` Fuzz, a `_p` Parallax, a `_g` Emissive, and an `_s` Subsurface (Foliage when the set's scanned meshes are Tree Anim, or its path is under a trees or plants folder and there is no scan; Coat diffuse while Multilayer is on). They read "(auto)", with the reason on hover, and are written to the JSON. Untick one to store an explicit off, which wins; reset removes it. Removing the texture removes the auto value. Nothing is saved to the project until you set it.
- **Subsurface** is one selector, the first row of the Subsurface group: **Off / Standard / Foliage**. Standard writes `subsurface`, Foliage writes `subsurface_foliage` (the Tree Anim term in Community Shaders), Off writes neither; it never writes both. The Subsurface group's colour and opacity show for Standard and Foliage. A project that stores both shows "Standard + Foliage (conflict)" and is not rewritten until you pick a mode. Export asks first on a conflict, on Foliage for a set whose scanned meshes are not Tree Anim, and on Standard for a set whose scanned meshes are Tree Anim (these two need a scan). Foliage needs an `_s`, like Standard.
- A feature that is on without its texture blocks export.
- **Reset** (↺) returns one field to its default. There is no whole-set reset; "Reset all settings for N selected…" clears the selected textures' own entries.
- PGPatcher's own `default` block is fixed: you cannot edit defaults. Each entry writes `emissive`, `parallax` and `subsurface` only when on, and omits the three numbers when unset or equal to the fixed value.
- Numbers cannot go below 0, and strengths, weights and opacities stay within 0–1. A typed value outside the range is clamped, and the box says "clamped to ≥ 0" or "clamped to 0–1". A value hand-edited in `sdc-project.toml` shows as it is, with the same note, and the JSON gets it clamped. The glint log density has no limit. Each number drags at its own speed and shows its own number of decimals (Task 14b): angles in half-degree steps, the specular levels in thousandths, the glint density randomisation in whole numbers; keys whose useful values span a wide range (displacement, emissive scale, specular levels) speed up as their value grows.
- **Matching** lists the exact texture paths the entry matches (PGPatcher's `match1`–`match8`). The entry applies when any of them matches. The diffuse path is on by default. The **+** button adds a row for slot 3–8. A slot that holds a texture starts from the set's path for it; any other slot starts empty and says "this row matches nothing until a path is entered" (an empty row is not written to the JSON). **×** removes a row. A set that matches nothing is left out of the JSON, and Export asks first. A renamed set has one match: it says "renamed: matches by diffuse (PGPatcher rename needs match_diffuse)", and its entry is written as `match_diffuse` + `rename` with no `match1`–`match8`. **+**, **Match on this** and the JSON editor's Match entries are greyed out while it has its one match, with the reason on hover. Extra rows from before the rename stay, say "not written", and Export asks about them. Path contains is treated the same way: a renamed set takes none, and one already there is not written and marked so.
- **Advanced TruePBR settings** (collapsed) holds path contains, mesh path contains, rename, UV, vertex colour and lock keys. **Rename** takes a new file name only (no folders): the outputs keep the matched texture's folder under `textures\pbr\` and take the new name, and Tessalith writes it to the JSON next to the matched diffuse as `match_diffuse`, the key PGPatcher renames from. If matches point at different textures and Rename is empty, a warning says the output prefix depends on which one hits first: edit the match paths so they point at the same texture.
- **Colour fields.** Every colour input (the TruePBR colours, the 3D View background) has a swatch that opens a colour square and a `#RRGGBB` box (the `#` is optional, case is ignored). The box commits on Enter or focus loss; invalid text gets a red outline and is not applied. Beside a TruePBR swatch (the coat colour included) are three number boxes, one float per channel (3 decimals) from 0 to 10: a channel above 1.0 is real (fuzz colour 1.25 is common). The swatch and the hex box show the colour clamped to 1.0 and write 0-1 values only when you change the colour through them, so opening the colour square and closing it leaves a stored 1.25 alone. The JSON gets the value as stored (0.08 stays 0.08). A colour saved by an older version as 0-255 whole numbers still reads the same (value/255) and is written as before until you edit it. Switching **Fuzz** on starts from colour 0.08, 0.08, 0.08 and weight 1. The 3D View background (*Solid*) takes any colour.

### Advanced skin card

A set whose diffuse is an **Advanced skin** (`skin_albedo`) gets an **Advanced skin (Community Shaders)** card instead of the TruePBR card. It lists the set's skin textures (`_rfaos`, `_sk`, `_wet`) and the 20 per-material Community Shaders skin settings in five groups: Specular, Physical, Edge & detail, SSS and Fuzz. Wetness is not here: Community Shaders keeps it global.

- **Choosing the Advanced Skin shader** on a set's card (Community Shaders target) also makes the set's diffuse `skin_albedo`, so a packed `_rmaos` becomes `_rfaos`, in the same undo step. It does this when the diffuse's sub-type was inferred or is plain `diffuse`; a sub-type you picked yourself (say `pbr_albedo`) is kept. Choosing another shader, or Auto, puts back what was there before (inferred, or your `diffuse`) and the packed output returns to `_rmaos`, unless you have changed the diffuse's sub-type since or pinned its slot. Tessalith remembers which diffuses it changed in `sdc-project.toml` (`[project] auto_skin`).
- **The shader decides the reading, unless the diffuse is pinned.** While a set's shader is Advanced Skin, its diffuse reads as `skin_albedo` whether its sub-type is inferred or written as plain `diffuse`; only another sub-type you picked yourself stays. A pinned Diffuse slot blocks this: the set reads and packs as it would without the shader (Tessalith writes nothing into a pinned slot), while a diffuse already written as `skin_albedo` keeps it. The packed output is `_rfaos` (RFAOS (skin) (auto) on the card) when the set can build one and the card's recipe does not say RMAOS; a set with only a metallic map, or with a pre-packed `_rmaos`, keeps it. This holds for sets saved with Advanced Skin before this behaviour existed: they switch on open, with nothing written.
- Each setting is **not set** (the Community Shaders default shows beside it, e.g. "default 0.7", and nothing is stored) or an explicit value on this set. **set** stores the default as a value you can then change; **↺** returns it to not set. Presets, defaults and rules never fill these, and sets do not inherit from each other.
- Values are saved in the set's `skin` table of `sdc-project.toml` under the Community Shaders key names. Keys Tessalith does not know are kept.
- **Saved in the project; not written to Community Shaders yet (export spec pending).** Export does not change for these. The card's **Export JSON** section is a greyed-out placeholder until that export is specified.
- **No PGPatcher JSON.** A skin set has no TruePBR card, no PGPatcher JSON entry (the next export that writes the JSON leaves it out), no entry in the JSON editor and no PGPatcher checks; its set card's pill reads "skin" and its hover "Advanced skin (no JSON)". Its textures still encode as skin textures. If no PBR set is left, the JSON is not written at all and the old file stays as it was.
- **Where skin sets write.** A skin set's files go to their normal paths (mirroring the source folders), not under `textures\pbr\<prefix>\`, and **Rename** names its outputs with an output name, as for any set without JSON. Files an earlier export wrote under `textures\pbr\` stay until you delete them.
- Number boxes clamp to a sensible range (0-1, 0-4 for multipliers, 0.1-100 for the detail tiling) and keep 4 decimals. Each edit is one undo step, and a drag on one value is one step. Bulk edit does not touch these.

### NiAlphaProperty

The TruePBR card has a collapsible **NiAlphaProperty** section for the schema's `alphaprop_*` keys (they set the alpha blending and alpha testing of the shape in the NIF). **Override flags** writes `alphaprop_flags`; the controls under it (Enable blending, Source and Destination blend mode, Enable testing, Test function) compose the number as NifSkope does, and "= 4844" shows it with an **edit raw** box (0-65535; anything else is outlined red and not written). **No sorter (no effect in Skyrim SE)** comes last: a RenderDoc capture showed the game draws a blended shape in its stored triangle order whether bit 13 is set or not, so it is kept only so a stored value round-trips; Tessalith never sets it. Switching it on starts at 4844: testing on, Greater, Src Alpha / Inv Src Alpha, blending off. **Alpha test threshold** writes `alphaprop_thresh` (0-255, starts at 128). **Create NiAlphaProperty if missing** gives shapes without one a new property; without it the flags and threshold only change shapes that already have one, and Export warns about that. **Delete NiAlphaProperty** removes the property and wins over the other alpha keys of the entry (they are greyed, and Export warns if any is set). A key that is off is not written. Each key that is set has a **reset** button. A hand-edited `4844.0` reads as 4844; a negative, fractional or too large value shows an amber "stored … is not valid" note (the key counts as set, and the first edit replaces it). The JSON editor lists the same keys.

### The JSON

After a complete export, **Export** writes `<export>\PBRNIFPatcher\<name>.json`. Only sets that exported fully are written, and the file name must be a single plain file name. If the file already exists and is not the one sdc wrote last time, you are asked before it is overwritten; a byte-identical file is never prompted. With a read-only `sdc-project.toml` the JSON is still written, but the next export asks before overwriting.

### The JSON editor

**Open the TruePBR JSON editor** (**PGPatcher JSON editor…** in the header's **Export to ▾** menu (**More ▾** until a folder is chosen), the **TruePBR JSON editor…** button beside the Material tab, or the command palette) shows the whole PGPatcher JSON as a tab of the centre column, with **Pop out**, **Dock** and **Close** as the preset creator has (see [Presets](#presets)): one entry per TruePBR set, then the delete sections. Advanced skin sets have no entry. Its top field, **JSON name:**, is the JSON's file name (by default the folder name, shown as gray hint text; empty restores it), with the full path beside it; a change applies when you leave the field, as one undo step.

- The header reads "N errors, M warnings". Errors are what blocks Export (a red line under the entry they belong to); warnings are what Export asks about (an amber line). A problem that belongs to no entry (the JSON name, a set that matches nothing) is listed in a **General** box at the top.
- **Next error** and **Prev** (F8 and Shift+F8) jump to the next or previous entry with an error, unfold it and scroll to it. They wrap at the end. Each entry has a **Collapse** / **Expand** button.
- The search box keeps the entries whose set name or any path in them (match, slot, path_contains, nif_filter) contains the text, ignoring case; "showing K of N" says how many are left. The counts and Next error ignore the search: if the next error is hidden by it, Next error clears the search. An entry shown struck through because a delete section hits it carries no count: "0 warnings" can sit above it.
- The JSON text is built again only when something it is made from changes, not on every frame.

### PBR Landscape

Under the Community Shaders target a PBR set (an `_rmaos`, a PBR albedo or the raw PBR maps) under `textures\landscape\`, with a `landscape` folder in its path, or with a Community Shaders texture-set block gets the **PBR Landscape** shader automatically; you can also pick it in the Shader list. It converts exactly like a PBR set; only the cards and the set's pill change. Its maps are the albedo (a landscape diffuse or plain diffuse also fills it), `_n`, and optionally `_rmaos` and `_p`.

The set editor shows a **PBR Landscape** card, open by default. It edits the same blocks that the **CS PBR records** panel edits for other sets (a PBR Landscape set has no such panel). At the top, **Also write into the PGPatcher JSON** replaces the statics choice. Until you click it, it follows the scan: with no scan yet the entry is written; after a scan it is ticked, with "Used by N meshes", only when meshes that are not LOD use the diffuse. A click stores on or off, and **Back to auto** returns it to the scan. A set whose colour map is a landscape diffuse rather than a PBR albedo has no PGPatcher entry: the box is off and greyed and says how to change that. Below the box come the texture set (template, the fields, the EDIDs with suggestions from the scan; the first edit creates the block, and only Undo or picking PBR removes it again) and a **Material object** section (add or remove, template, fields, EDIDs). Fields show plain names; hover one for its exact JSON key. The card starts with a **Shared** section holding the glint parameters, which the texture set and the material object read the same way, so one edit writes both. **Unsync** in the Material object section gives it its own value, and **Sync Glint parameters** takes the shared one again. Roughness and specular stay separate rows because they mean different things: the texture set's values multiply the `_rmaos` map, while the material object's replace it (the hover says which). Community Shaders' landscape shader reads only roughness, displacement, specular and glint, so while the box is off the subsurface, coat, fuzz and inner-layer rows are hidden (one line says how many), unless they hold a value. With the box on they show, because the meshes that share the texture read them. Under the card, **PGPatcher JSON settings** (a framed group) holds the TruePBR panel: open while the entry is written, collapsed and marked "not written" while it is not.

The pill on the set's card says what the set writes (the hover has the long form): "PBR Landscape → CS + PGPatcher JSON", "→ CS JSON", "→ PGPatcher JSON (no CS records yet)" or "PBR Landscape (no JSON yet)". CS records are written for a block with at least one EDID. In the 3D preview a PBR Landscape set is shown on the plane, like a set with a texture-set block. Any PBR set under `textures\landscape\` counts, trees, grass and mountains included; pick PBR in the Shader list for one that is not terrain.

### Community Shaders PBR records

A set can also write Community Shaders' own runtime files: a **PBR texture set** (`<export>\PBRTextureSets\<EDID>.json`) and a **PBR material object** (`<export>\PBRMaterialObjects\<EDID>.json`). Open **CS PBR records** (collapsed; its header reads "N records") in the set editor's Material tab and add either block. A PBR Landscape set has no such panel: its card edits the same blocks.

- **Template** fills the block's values from the built-in library. PBR landscape template values by Faultier (https://www.nexusmods.com/profile/Faultierfan?gameId=1704), from Faultier's PBR landscape modders resource. A block with no EDIDs takes the template's EDIDs; EDIDs you added are never removed.
- **EDIDs** are the records the file is for, and the file name is the EDID exactly, case included (Community Shaders matches the exact case). After a plugin scan in the Meshes view, texture-set EDIDs are suggested from the texture sets that use the set's diffuse, and material objects can be picked from the scanned records. A warning says when an EDID is not in the scan, differs only in case (one click fixes it), or names a material object that is not single-pass (Community Shaders ignores the file then). An EDID that cannot be a file name, or that two sets bind, is not written.
- A texture set also drives the set's PGPatcher entry: roughness, specular, displacement, subsurface and coat values and glint come from the block, so the two files cannot drift. The entry is written only when the latest scan finds meshes (not LOD) that use the set's diffuse; **PGPatcher entry for statics** can force it on or off.
- Every number is written with a decimal point. A file you edited outside Tessalith is never overwritten (the export report says so; delete it to let Tessalith write it again), and a file Tessalith wrote for an EDID no set binds any more is reported, not deleted. If `sdc-project.toml` changed on disk while the export ran, recording the written JSON files asks **Overwrite with my changes** or **Reload from disk**, as a save does (the same holds for the PGPatcher and complex material JSON).
- In the 3D preview a set with a texture-set block is shown on the plane, with a **Tiling** slider (1× to 3×) that only changes the preview. The tiling is one value for the session and stays when you switch sets.

## Complex grass

A complex-grass texture is one image twice as tall as it is wide: diffuse and alpha on top, normal and specular below. Pick **complex grass** as its sub-type (under *Packed and data*), or let sdc tag it after a Meshes-page scan that included plugins: a texture used by a GRAS (grass) record, 1:2, with a valid detection corner and a normal-map bottom half is tagged automatically. Both targets have it; only Community Shaders or ENB read it in game. Warnings name what is wrong: `GRASS-SHAPE`, `GRASS-TOP-OPAQUE`, `GRASS-NORMALS`, `GRASS-DETECT-SOURCE`. The CLI never auto-tags, but the GUI writes the tag into `sdc.toml` (`[files]`) when it tags a file, so `sdc convert` on a folder saved from the GUI encodes it as complex grass too.

## PBR grass

Community Shaders draws grass with its own shader, which reads only the albedo, `_n`, `_rmaos` and an optional `_s`. A PBR set whose albedo a grass (GRAS) record uses gets the **PBR grass** shader automatically after a Meshes-page scan that included plugins; you can also pick it in the set's Shader list (Community Shaders target only). The TruePBR panel of a PBR grass set shows only what grass reads: roughness scale, specular level, subsurface (Standard or Foliage, on automatically when the set has an `_s`), matching, vertex colours, locks and slots. The JSON editor shows the same grass view, and its "+" menu does not offer the hidden keys. Other keys the set already has stay in `sdc-project.toml` and come back if you switch the set to PBR, but they are not exported. PBR grass meshes need PGPatcher 2.1.0 or later to be patched. `PBR-GRASS-DETECT` on the albedo means its bottom-left texel looks like a complex-grass normal, so Community Shaders' grass shadow pass would cut the shadows wrong; change that texel. The check covers single-file albedos only: a packed albedo gets no note. The 3D preview draws PBR grass with the object PBR shader and says so; it does not claim UV scale applies. The command line never picks PBR grass by itself; use `--set set:<id>.shader=pbr_grass`.

## Generate from normal map

Many sets ship a normal map but no height. **Generate from normal map…** integrates the set's normal back into a height map and writes it as a source file next to the normal. Nothing changes until you click **Generate**. A small **Generate…** button also sits directly under **Assign…** on an empty Height or RMAOS row (and under the format combo on a filled one; it reads **Regenerate…** when a generated file already fills the slot); it is hidden when the slot's item is a packed texture. In the preview, the wheel zooms 1 to 16 times around the pointer, a drag pans, and a double-click fits; all tiles share one crop.

- **Where:** the Height row's right-click menu (an empty row's **Assign…** opens the same menu), and the set card's menu. The entry is greyed out with the reason when the set cannot use a height (vanilla multilayer, vanilla landscape, a shader that reads no height, no normal map, a normal whose sides are not powers of two, a real height already there).
- **The dialog:** Size (256, 512 or 1024, up to 2048 on a cs PBR set whose albedo is larger, never larger than the normal; above 512 a warning about parallax cost; the `_m` alpha takes the `_m`'s size), Tiling (Auto, Wrap, Mirror), Relief balance and Strength, with a preview of the height and the fit. It shows the path it will write. On a complex-material set (vanilla target) **Use as** offers *Complex material `_m` alpha*. Enter never generates.
- **Names:** `<base>_p_generated.png`, or `<base>_height_generated.png` for the `_m` alpha, next to the normal, as 16-bit grey PNG. They are ordinary sources: the CLI reads them too. A file that is already there is never overwritten.
- **Two ranges:** 0.5 is "no shift" for Parallax, PBR, complex material and landscape; 1.0 is "no shift" for a PBR multilayer set with inner-layer (coat) parallax. Vanilla multilayer is not offered.
- **A real map always wins.** If a real `_p` (or `_height`) appears later, the generated file is skipped with the Info note `GEN-REPLACED` and the row offers **Delete generated file…**.
- **Side effect:** a new `_p` wins the shader auto-pick, so a default set becomes Parallax and PGPatcher patches its meshes. On a TruePBR set the `parallax` key turns on by itself (auto flags, Note AJ).

Where it shows: the Height row's File cell hover adds "Generated from {normal}", and its Flags cell has a weak **generated** marker. When the generated file is out of date (the normal changed, the set now wants the other neutral, or the set's shader reads no height), that row's status dot turns amber, with "stale: {reason}" on its hover (`GEN-STALE`, Info). It is also in the texture's message list, and a Problems warning row on the generated map with **Regenerate…** (Note FC3), so its set's dot is no longer ready until you regenerate. `GEN-REPLACED` is never a Problems row. A `_height_generated` for the `_m` alpha has no row of its own: the `_m` block's alpha line carries the hover and a weak stale line.

**Regenerate…** (the same entry once a recorded file exists) opens the dialog with the settings the file was made with, corrected to the neutral the set wants now and to a size the normal still offers. It replaces the file only if it is unchanged since Tessalith wrote it; an edited file is refused with "…was edited since it was generated…". **Delete generated file…** (on the row, and as a submenu of the set card's menu) asks first: Cancel is the Enter default and Delete is outlined red. The box says when the file was edited since it was generated, or when Tessalith has no record of generating it; your confirm deletes it either way, takes it out of the set if it was moved in with its normal, and forgets its record. A file that changes while the box is open is kept. The set card's submenu also names the real map that replaced a file. It cannot be undone. The records live in `sdc-project.toml`'s `[generated]` table, outside Undo. They are also written at once to `_sdc/generated.json` beside `sdc-project.toml` (Note FC11), with the JSON hash records, so a file you generated and then closed without saving is still "generated here" next time; opening the folder copies them back into `sdc-project.toml` quietly (no unsaved changes; the file catches up at your next Save). Where the two disagree, `_sdc/generated.json` wins over a hand edit of `sdc-project.toml`.

### AO

The same dialog makes an ambient-occlusion map from the normal (a horizon march over the solved height). A baked AO is better: use this only when the set has none.

- **Where:** the `_rmaos` row's right-click menu (an empty row's **Assign…** too), the set card's menu (the dialog's **AO** checkbox), and Regenerate. It is offered only for PBR, PBR landscape and PBR grass sets on the `cs` target, whose `_rmaos` reads it; elsewhere the entry and the checkbox say "AO is generated only for PBR sets under Community Shaders". It is also greyed out when slot 6 is pinned, when the set already has an AO source (a real `_ao`, or a pre-packed `_rmaos`/`_rfaos` image whose blue channel already holds AO, named with "(B)" in the reason, or one beside a loose roughness, metallic, specular or `_orm`), or when its `_rmaos` is a DDS (never re-encoded). A pre-packed image whose blue is flat white gets the generated AO in B, with R, G and A kept from the image.
- **The AO group:** Radius (1.5625–25 % of the width, default 6.25 %, with its size in texels), Quality (8, 16 or 32 slices; 16 steps), Depth (0.25–4) and Intensity (0.5–3; the file holds raw visibility and CS applies AO to indirect light itself, so 0.7–1.0 is a good range). The preview runs at 8 slices × 8 steps and adds "AO: mean …, … % of texels below 0.5".
- **Size:** with only AO ticked, the Size is AO's own default. One Size for all ticked maps, each capped at its own limit (the height at 1024, or the albedo's size up to 2048 on a cs PBR set; AO at 2048). When the set has other `_rmaos` sources (roughness, metallic, specular), the AO takes their size, shown read-only, because a packed `_rmaos` needs one size; a normal smaller than them disables AO with the reason. The path lines show each file's size.
- **The file:** `<base>_ao_generated.png` next to the normal, 16-bit grey. On the next plan it is the `_rmaos` B channel, with the Info note `GEN-AO` in place of `PACK-DEFAULTED`. It fills no row of its own: the `_rmaos` row's File hover says "AO generated from {normal}" (no **generated** marker: the packed `_rmaos` itself is not generated), its AO fill line says "Generated from {normal}", a stale AO turns that row's dot amber, and that row's menu offers **Delete generated file…**.
- **Bent normals:** when the set's normal has an RNM bent layer and AO can be generated for it, the dialog says at the top that a generated AO also changes the normal map, which is weighted by AO.

### Curvature

The dialog's **Curvature** checkbox writes `<base>_curves_generated.png`: the Laplacian of the same height solve, smoothed over about 2 texels at the solve size (up to 1024 px; a 2048 curvature is upsampled, so about 4 of its texels), 0.5-centred, with peaks bright and hollows dark. Its hover says "used by Also export as: Vanilla / Complex material": it is read only by Also export's soft-light step, so a plain export reports it as `PACK-UNUSED-INPUT`, which is expected.

- **Where:** the set card's menu (the dialog's **Curvature** checkbox) and Regenerate. It has no slot row. It is offered only where Also export reads it: PBR, PBR landscape and PBR grass sets on the `cs` target with no DDS member (Also skips such a set). Elsewhere it says "curvature is read only by Also export, which reads PBR sets under Community Shaders", or names the DDS. It is also greyed out when the set has no normal, the normal is not a power of two, the set already has a real `_curves` or `_curvature` map, or a `_curves_generated` file Tessalith did not write is there.
- **Size:** the set's albedo size, shown read-only, because Also's diffuse reads the albedo and the curvature together. A normal smaller than the albedo, or an albedo whose sides are not powers of two, disables Curvature with the reason. A set with no albedo of its own (a borrowed diffuse does not count) gets no Vanilla diffuse from Also, so Curvature is greyed out there too.
- **Provenance:** with no row, its stale reason, Regenerate and **Delete generated file** are on the set card's menu. The set card's **Regenerate…** opens with the set's first recorded map ticked and the settings it was made with (Tiling, green, Relief balance, Strength, AO settings).

## The preview

Double-click a tile (or a set member), or select it and press **Enter** or **Space**, to expand it into a preview with a Source side and an Encoded side. **Esc** or a double-click in a viewport collapses it again. In the preview, **[** and **]** step to the previous and next texture in the order the Textures column shows, **1** to **6** pick the channel buttons from left to right, **PageUp** and **PageDown** step through the mips, **L** turns the lens on or off and **T** the 3×3 tiling.

- **Live encode** is **off by default**. Encoding happens when you press **Encode now**; switch Live encode on to encode after every edit (a short pause after each edit, then the encode starts). A result that no longer matches the settings is badged *stale* until it is replaced.
- Each previewed mip is byte-identical to the same mip of the DDS that Export writes, except for a texture on NVTT: its preview uses the built-in encoder and says "Preview uses the built-in encoder; the export uses NVTT."
- The preview encodes only mips whose larger side is at most the **preview size limit**: **4096 by default**, settable to 1024, 2048, 4096 or 8192, and 16384 only after you tick *Allow 16384 previews* in Advanced. A GPU that cannot hold a texture that large lowers the limit and the preview says so.
- **Toolbar.** Three labelled clusters in one wrapping flow, with only **✕ Close** pinned to the right: **Channels** (RGBA, R, G, B, A and the alpha mask), **View** (*Side by side* or *Split*, *Pin this result* and its Compare controls, a *Heatmap* of the difference to the source, *Lens*, *Tile 3×3*, the *Range* and *UV coverage* overlays (see Artist checks), *Fit*, *1:1*, and the exposure slider for HDR formats) and **Encode** (*Live encode* and **Encode now**). After them come the sRGB / UNORM display (both panes show the values the file stores, so a source and its encode look alike under either) and the mip slider. A narrow toolbar wraps onto more rows in that order instead of clipping; a row that appears is drawn on the next frame. **Encode now** is filled in the accent colour while it can encode and plain while it cannot (the selected toggles keep egui's own selected look). Scroll zooms and dragging pans. Readouts under the viewports show the PSNR, alpha and normal-length checks for the mip on show.
- **Texel readout:** point at the picture and the strip under the viewports shows the texel under the cursor: its coordinates at the mip on show, the source and the encoded RGBA as 0–255 and as floats, and the difference per channel with its largest (the channel the heatmap measures). The numbers are the stored values; the first line says how the view reads them (sRGB-encoded, or linear under UNORM; HDR formats show floats only). A channel button narrows the readout to that channel. For a normal map it also shows both normals as vectors, the encoded one's length and the angle between them in degrees. A side the preview does not hold (no encode yet, a DDS input's source, a mip above the limit) shows "—". Side by side and Split read the same texel for both sides.
- **Lens** (**L**): a circle 160 points across that follows the cursor and magnifies the view 8× with no smoothing, centred on the texel under the cursor with a crosshair. It shows in both viewports (in Split, each side of the divider shows its own side).
- **Tile 3×3** (**T**): the picture repeats three by three, to check the seams. Zoom, pan and the readout work on the tiled view; *Fit* fits all nine copies.
- **Exposure:** for HDR formats (BC6H, RGBA16F) a slider from −8 to +8 EV scales the values by 2^EV before the tone map. It starts at 0 for every texture.
- **Heatmap legend:** with the heatmap on, a colour bar under the viewports shows the scale from 0 to the *full scale* (the difference drawn white), which a slider sets from 0.005 to 0.5 (0.1 by default, about 25 codes of 255). The heatmap is made in the background. While a new one is made after a full-scale change the previous one stays on show (a result for an older scale is shown as soon as it lands, so dragging the slider never blanks it); after a mip change the plain image shows instead, because a heatmap of another mip does not fit. The legend label reads "updating…" greyed until the current heatmap is ready.
- **Pin and compare:** *Pin this result* (**P**) in the toolbar keeps the encode on show, with the settings that made it, so that the next encode can be compared against it ("is NVTT, or a higher effort, worth it on this texture").
  - **What it keeps.** The finished encode for all its mips (not re-encoded), and a summary of its format, colour tag, encoder and effort, alpha policy and mip options, and its PSNR against the source. The button is off until the encode on show is finished and matches the settings (not stale). Pinning again replaces the old pin, so there is at most one.
  - **When it goes.** Closing the preview, moving to another texture and opening a folder drop the pin and free its images and its GPU texture. *Unpin* drops it too. Changing settings on the same texture keeps it: that is the point.
  - **While pinned.** *Compare: Source | Pinned* sets what the left side shows in *Side by side* and *Split*. *Pinned* puts the pinned encode on the left and the current encode on the right (pinning turns it on). Each side has a caption with its settings summary and its PSNR against the source. The texel readout adds the pinned values and the difference between the pinned and the current encode (two more lines), the lens magnifies both sides, and the heatmap shows the difference between the current and the pinned encode, labelled "Current vs Pinned". If the pinned encode has no mip you are on (it was made under another size limit), the left side shows "— not in the pinned encode".
- **Minimum width and the settings strip.** The preview never gets narrower than 480 points of picture. While a texture is expanded, the Textures and Sets columns and the Advanced drawer give way to keep that (the centre needs at least 520 points: the 480, the 24-point strip and the panel margin; from 1280 points wide, 776, with the 280-point settings panel in place of the strip), and they get their chosen widths back when the preview closes. The texture's settings sit in their own panel on the right of the preview. In a window 1280 points wide or wider the panel starts open, and opening Advanced does not collapse it (Note FC8); with Advanced open at 1280 the picture can then be narrower than 480. In a narrower window, when the panel does not fit beside a 480-point preview, it starts as a narrow **Settings** strip; click it to open the panel. Once opened, the settings stay open until the preview closes, including when you expand another texture directly. The Advanced drawer keeps the width you dragged it to and is not saved to `gui.toml` until you drag it.
- A DDS file in the folder previews as stored (there is no source side). Uncompressed DDS files preview from the CPU decode; BC2 and signed BC6H show "cannot be previewed" (N11 ended in M6).
- With no usable GPU the preview is off and says "No usable GPU: the preview is off; everything else works"; deciding, editing and Export still work.


## The 3D preview

The Meshes view's 3D panel and a set's 3D view work the same way.

**Layout.** Both panels have one toolbar line, the frame in all the height left, and a **Details** footer under it, collapsed until you open it (each panel remembers it in `gui.toml`). The toolbar holds, for a set, *Encoded (exact export)* | *Source (faster, no compression)* and the **Mesh** list ("Mesh: Auto (Sphere)"; the scanned meshes list loose files before BSA ones, and ground models (a `gnd` word in the name, or a name ending `gnd` or `_go`) and `1stperson` meshes last, so *Auto* takes a loose, normal mesh when there is one), then for both **View ▾** (debug view, **Accurate (deferred)**, background, lights, Reset view; it stays open while you use it), **Copy image** and **Shader folder…**. What needs attention shows as a line between the toolbar and the frame, never in Details: a map that failed, is stale or is blocked, a skipped shape or a patch badge, a shader that failed, an error, a missing texture (in magenta, with *Open in Textures*), "PGPatcher preview needs the CS target and a PBR set", Community Shaders not found, and the notices. Details holds the rest: "Assumes your Tessalith JSON wins…", the preview size, the mesh line ("No scanned mesh uses this diffuse"), each map's encode time, the built-in shape line, the emissive note, Timings, the Community Shaders features toggle, "Off in this preview: …" and the frame stats.

**A set in 3D.** The **2D | 3D** switch at the left of a set's header row (next to its input name box) changes the centre pane in place. *2D* (the default) shows the set editor: the slot rows and the TruePBR settings. *3D* shows the set's 3D view across the whole centre instead; the header row stays above it. **TruePBR settings…** in the header row opens a window you can move and resize with the set's TruePBR settings (the coat settings under Multilayer, NiAlphaProperty and the rest), for an Advanced skin set, the skin card, the PBR Landscape card or the CS PBR records (Community Shaders target) and the complex material card when the set has them; an edit there shows in 3D right away. Whether it is open, and where, is remembered in `gui.toml`. While the switch is on 3D, selecting any texture of a set (from the set or straight from the Textures column) shows that set's 3D view, and the window (titled *<name> settings*) shows the texture's own settings above the set's. The window follows the selection, and closes when the new selection has none of these settings. A texture in no set shows its normal settings; the switch stays on 3D. The switch is remembered in `gui.toml`, and the 3D view does no work while 2D is showing.

- **Moving around.** Drag to orbit, scroll to zoom. Middle-drag, or Shift+drag, pans: the model follows the cursor, and the further away the camera is, the more a drag moves it. Double-click or **Home** recentres the camera.
- **Turning the sun.** Shift+right-drag turns the sun around the model (about the vertical). The studio HDRI background and its light turn with it. The turn is part of the View controls, so it is remembered with them.
- **Debug view** (in *View ▾*, or **V** to step through): *Lit* is the normal Community Shaders render. *UV checker* puts a grey checker in every shape's diffuse (base colour) slot, so stretched, mirrored or seamed UVs show; the rest of the material still draws. *Albedo*, *Normals*, *Roughness*, *Metallic* and *AO* show one channel of the material. They are offered only when the Community Shaders build in use allows it and a loaded shape has that channel; where a shape has only a stand-in (non-PBR roughness as 1 − specular mask, vertex AO), the hover names it.
- **Accurate (deferred)** (in *View ▾*, on by default): opaque shapes draw through Community Shaders' own deferred pass and composite, as in game; blended shapes still draw on top the forward way. Off uses the older forward path. If your Community Shaders build cannot run it, the view stays forward and a notice says why. The setting is remembered.
- **Missing textures** show in solid magenta in the frame (colour slots only; a missing normal, glow, specular or RMAOS map draws neutral), and are listed above it in magenta. A path that is a texture of the open folder has a *Open in Textures* button that selects it in the Textures view. A missing cube map (an environment map) keeps the renderer's plain stand-in instead, because a flat colour cannot go in a cube slot.
- **Reset view** (in *View ▾*) puts the lights, the background and the camera back to their defaults (not *Accurate (deferred)*).
- **Copy image** (or **Ctrl+Shift+C**) copies the last frame to the clipboard, at the size it was rendered; the panel says "Copied 3D view (W×H)".

## The Meshes view: shapes

**The header.** The Meshes view draws the same one-row header as the Textures view (Open, Undo, Redo, MO2…, Mode, Preset, the view tabs, Export to, Save, Export) with the status line under it; only the column eyes are missing.

**Scan source and progress.** The scan source is behind the **MO2…** header button (both views): a popup with the instance and **Choose…**, the instance's profiles, **Scan a folder…** and **Scan** / **Cancel**, which stays open while you click in it. While a scan runs, the scan row (in the Meshes view and in the Textures view) shows a bar with the phase and its count, for example `reading 120/4000 · ETA 0:42`. The ETA appears once the phase has finished 3 items or run for 2 seconds. The ETA is the average over the last 10 seconds, as in the Files tab, and starts over with each phase.

**The mesh list** (Note GC). The left column lists every mesh path once, with the copy that wins in game: the path (without `meshes/`, cut to the column, full path on hover), its mod, and its chips, warnings first: **Problem**, **Stale patch** (PGPatcher patch out of date), **LE**, the edit badge, the status chip (**Wins**, **In game** for "Patched by PGPatcher (in game)", or **Overridden**), **PGPatcher**, and the mod's **Generated** (by PGPatcher), **BSA** or **game Data**. Chips that do not fit are cut; hovering the chips lists every one in full, with the copies and the problem's text. **Search paths and mods** keeps the rows whose path or mod name holds the text (ASCII case does not matter, `\` reads as `/`, a leading `meshes/` is ignored). The **Any mod** box picks one mod with meshes (PGPatcher's output mod is not offered) and lists all of its copies. The chips are *All*, *Wins* (with a mod picked only), *Overridden* (under **Any mod**, every losing copy with its own mod), *Conflicted* and *Problems* (a problem or an LE mesh). A count line reads "N of M NIFs" and adds "(the selected NIF is hidden by the filters)" when it is: filters and the picker never deselect. The rows are read in the background after a scan or reload ("Reading the scan…"); with no scan the column says "No scan yet."

Next to the **Meshes** title is a **Shapes** button (greyed out, "Select a mesh first", until a mesh is selected). Switched on, it replaces the mesh list with the shape cards of the selected mesh; switched off, or when the selection clears, the list is back. While **Edit** is open the column stays on the shapes and the button is greyed ("Close Edit to see the mesh list"): the cards are where you pick the shape to edit. The right-hand pane always shows the 3D view. The column starts at 420 px and is at most 40% of the window, narrowing further as needed so the 3D view keeps at least 240 px (with the edit panel open too); its lists have thin scroll bars that stay visible. Closing Edit puts the column back on what it showed before (Edit keeps it on Shapes).

Each shape is a framed card. It shows, from the top:

- **#N name**, with the block type on the right, a button as wide as the card. N is the shape's PGPatcher 3D index, the number plugins use for its alternate textures (a shape outside the scene tree reads `#–`). Click it to select the card: it gets the accent outline, and **Edit** then opens on that shape instead of Root. A NIF with one shape opens on it. Hover for the NIF block index ("NIF block 12").
- **The shader**, in bold: the lighting shader type, for example **Hair Tint (6)**, or "Effect shader".
- **The textures**: each set slot with its path, indented, and one weak line for the empty ones ("(4 empty slots)"). A missing texture says "→ missing" in red.
- **Alpha**, in words: "Alpha: blend Src Alpha → Inv Src Alpha · test Greater, threshold 5". Blending or testing is left out when it is off, and "Alpha: none" shows when both are. A shape with no alpha property says "No NiAlphaProperty". Hover for the raw flags, for example "flags 0x12ED (4845)".
- **Controllers**: how many, and their names, with "(clip)" for one a clip drives, for example "2: Emissive multiple, Alpha (clip)", or "none". A shape with an effect shader lists only its alpha controllers (the editor does not read the effect shader's), and has no line when it has none. Outside Edit the line is read from the NIF file once per scanned copy (it appears a moment after the cards; a file that no longer reads simply shows no line); inside Edit it follows the edited file, unsaved edits included.
- **Details**, closed: the NIF block and 3D index, **SLSF1 0x…** and **SLSF2 0x…** (open one to list its set flags by name, for example "Specular (0)"; a bit with no known name reads "bit N"), the geometry line (skinned, vertices, triangles), which mod each texture comes from ("→ A (2 copies)") and the raw slot strings.

A texture path that is a texture of the open folder has an **Open in Textures** button, on the shape card and on the "Users of" list's title. It switches to the Textures view, selects that texture and scrolls it into view.

### Editing a NIF

**Edit** (next to the NIF's name in the Meshes view) opens the edit panel for the selected NIF; click it again to close the panel. The panel shows the file's data path and `Source: <where it came from>`. Edits never change the source file. They are kept in a small edit document in `.sdc\nif-edits` under the export folder, and the export (from Review) writes a copy there. The export folder is the Textures one, once you have chosen it for the project (**Export to ▾** in the header, or **Choose…** in Review); there is no default. Until you choose one the edit opens and works, the export says "No export folder chosen", and the edit document is kept in `%LOCALAPPDATA%\sdc\nif-edits` (one file per NIF) so it survives a restart; the first save into a chosen folder moves it there. Edits made with Tessalith 1.1 or earlier without an export folder are in `mods\sdc NIF Edits`; choose that folder in **Export to ▾** to reopen them (Tessalith never edits a NIF from that folder).

**Cards.** In edit mode the shape cards get a **Root** card first, then one card per shape. Click a card's header to select it; the tabs below edit the selected card. A line under the tab strip names it: "Editing: BodyMesh (BSTriShape)", or "Editing: Root (NiNode)". **Show only this shape** hides the other shapes in the 3D view. While you edit, the cards show the edited file: a change to the shader type, a flag, the alpha or a texture path shows on its card at once.

**Tabs.**
- **Shader** edits the BSLightingShaderProperty of the selected shape. The texture slots come first (type a path, **Browse**, or pick from the scanned textures; **Check that files exist** and **Filter textures** help), then the shader type, glossiness, specular, emissive, UV scale and offset and the per-type fields, then the SLSF1 and SLSF2 flag lists, closed until you open them (a list with a flag warning starts open, so its fix button is in sight). A texture path change shows in the 3D view at once.
- **Alpha** edits the NiAlphaProperty: **Blend**, source and destination, **Test**, function, threshold, plus **Add alpha** and **Remove alpha**. "Shown as the engine draws it" and "Shown as CS evaluates it (alpha ≥ threshold)" say how the preview treats the test. A blend pair the engine mapping does not cover is drawn as stored and marked "Not verified in game".
- **Controllers** lists the shape's controllers (alpha, shader float and colour, texture transform) with their start, stop, frequency, phase, cycle and the animated value, and edits their keys. See **Animation** below. Controllers of other classes are read-only.
- **Extra data** lists the extra data of the root or the selected shape: BSXFlags bits, string, integer, boolean and float values, BSInvMarker. **Add to root**, **Add to shape** and **Remove** change the list. Each row shows its own warnings under it, for example "BSXFlags must be named BSX". Above the type and name, a **Known** list fills in an entry the game or a plugin reads, with its type, name and a starting value; hover an entry for what it does. On a shape: **AnisotropicAlphaMaterial** (Community Shaders see-through look; starts at 3, woven fabric). On the root: **BSX**, **INV**, **HDT Skinned Mesh Physics Object** (type the physics xml path in **Value**; Add stays off until you do) and **Prn (unconfirmed)** (the skeleton node the item attaches to; not checked against a source yet). An entry that goes on the other owner is greyed ("Goes on the root", "Goes on a shape"), and so is one this owner already has ("Already on this root"). **Custom…** keeps free typing for anything else. BODYTRI is not offered: BodySlide and Outfit Studio write it. **Heel height (RaceMenu)** (shapes only; on the root: "The game ignores heel height here. Put it on a shape.") raises the actor so heels stand on the ground. It starts at the shape's stored value, **Calculate** fills it from the lowest point of the shape in bind pose (rounded to 0.1, still editable), and **Set heel height** writes it: the shape's HH_OFFSET is changed in place or added, and an SDTA the shape already has gets the same height in its NPC entry (a new SDTA only when **Also write SDTA** is ticked). It says when an earlier shape's heel height wins, and for `_0`/`_1` files it reminds you to apply the same value to the other weight file. Heel data anywhere but on a shape, and on a shape after the first shape in the scene that has some, warns under its row. A negative height says it lowers the actor. When the shape's HH_OFFSET is not a number the editor can set (another type), Set heel height stays off until that row is removed.

**Shared blocks.** The panel says when a block has more than one user.
- A shared alpha: "Shared by N shapes: editing will split." The first edit splits it, so only this shape changes. On the Controllers tab you click **Split alpha** first. If a clip also drives that alpha, it cannot be split yet.
- A shared texture set: "Shared by N shapes: editing makes a copy for this shape."
- A shared shader: "Shared by N shapes: shader edits change all of them." A texture path edit on a shared shader is refused, because it would change the other shapes.
- A shared interpolator: a value edit is a conflict ("This interpolator is shared by N controllers"), and the value row is greyed. A key edit copies the interpolator and its keys first, so the other controller's curve does not change.

On a PBR shape, the SLSF2 flags that CS reads differently (Fit_Slope, Multi_Layer_Parallax, Soft, Back, Rim and Effect lighting) get a dimmer "PBR: <meaning>" label, and the same text in their hover; a non-PBR shape shows only the vanilla names.

**Warnings.** Values are never clamped. A value outside the range the game expects, or a flag combination that looks wrong, shows an amber warning under the field (red for an error), sometimes with a **Fix** button. A red error that your edit introduced blocks the NIF's export. An error that was already in the source only warns. Three flag warnings come from the corpus census: shader type 11 without the Multi_Layer_Parallax flag (SLSF2 24) and without PBR; SLSF2 24 on a shader type other than 11; Fit_Slope (SLSF2 12) without PBR. On a True PBR shape an empty slot 5 is amber: "Slot 5 (RMAOS) is empty: in game the mesh renders fully metallic".

**Flags that need a shader type.** The skin tint flag (SLSF1 21) works only on the Skin Tint type and the FaceGen detail flag (SLSF1 10) only on Face Tint (which needs it) or Skin Tint: a mismatch is a red error that always blocks the NIF's export, even in an untouched file, with a **Clear the flag** or **Set the flag** button; a type change fixes the flag in the same undo step and says so in a line under the type, and a flag that cannot apply to the current type is greyed with the reason on hover.

**Pending edits (N).** Every edit is a row in this list under the file name, named in words ("BodyMesh: SLSF1 flags"). A slider drag is one row. **Revert** removes that edit. Reverting a new or converted clip also removes the later timing edits of that clip, and its row says so: "(Revert also removes its clip timing)". A row in red did not apply, with the reason. The list is closed until a row turns red, which opens it; click its title to open or close it.

**Export status and Review.** The bottom of the edit panel, under the tabs, stays there however long a tab is. Its first line is a status: a green dot and **Ready**, a grey dot and "No edits to export." while nothing is edited, or a red dot and **Blocked:** with the reason. The reason is one of: an edit cannot be applied, conflicts are open, an edit introduced an error, or no export folder ("No export folder chosen"). When a pending row is red, **Show** opens the pending list. When a file Tessalith did not write is already at the export path, **Diff…** opens a list of the blocks that differ between that file and what the export writes, under the status line (it is read at the click; **Close** shuts it). Then "Writes meshes\…\x.nif to <export folder>\meshes\…\x.nif" (cut in the middle when long; hover for the full path) and "The source file is never changed. Change the folder with Export to ▾ in the header." **Review…** opens Review in the bottom panel: NIF edits export from there, with the textures, when you press Review's Export. The button itself never writes. In Review each NIF with edits is a row: its mod, how many unused blocks the export leaves out, and the result after the export (written, or skipped and why). A blocked NIF row is skipped and never blocks the texture export. Each write puts "Exported <path> to <mod>." in Messages, with a placement line when the mod order is wrong: when the export folder is a mod folder in the MO2 instance's `mods`, the export checks the mod order and says whether that mod must be enabled, or dragged below the highest source or above the lowest PGPatcher output; any other folder says "The export folder is not an MO2 mod here: load order not checked." and still exports. Changing the export folder while you have edits open keeps them in memory, unsaved; the next save or export goes to the new folder. If the new folder already holds saved edits for that NIF, your open edit replaces them: the first save there moves them aside to `<name>.<seconds>.toml` beside it, never overwriting them, and Messages names the kept file. The same happens to a folder's saved edits when a newer autosave of the NIF opens instead of them, and to an autosave this session did not open. The edits saved in the old folder stay there, and Messages names that file. If the edit document in the new folder cannot be opened (a file that does not read), the folder change waits: the edit stays blocked with "could not open the edit document in <folder>: <reason>", each save goes to the autosave in `%LOCALAPPDATA%\sdc\nif-edits`, and nothing is written to the old folder, until you choose a folder that works or go back to the old one. With no edits yet, the NIF's edits in the new folder open instead. After an export, the worklist has a Warning row "Re-run PGPatcher so its output includes this edit." when the NIF has a PGPatcher copy. The exported file leaves out the blocks your edits added that nothing uses any more (a removed controller or clip), so it can have fewer blocks than the edit shows. When that cleanup cannot read the file, an Info row says "Exports without cleanup: the file has a block Tessalith does not understand", and the export writes the file as edited.

**A file Tessalith did not write.** If the file at the destination is not the one Tessalith last wrote, its Review row waits for an answer, keep the file on disk or overwrite it, with neither picked. Until you answer, the export skips that NIF. An answer counts for one export, and only while the file on disk is the one you answered for: a file that changed since says "changed on disk since you answered" and asks again. The row's **Diff…** switches to the Meshes view and opens the edit panel's list of the blocks that differ.

**The NIF list.** A NIF with a saved edit gets a chip: **Edit pending**, **Edited** (exported and unchanged) or **Edit conflict**.

**Undo.** While an edit is open in the Meshes view, the header **Undo** and **Redo**, the command palette and **Ctrl+Z** / **Ctrl+Y** act on the NIF edit. With no edit open they act on the Textures history as before. The header buttons say which: **Undo** for the Textures history, **Undo NIF edit: Set shader type** (the step's name) for the NIF one, and the hover names the history (Note FC12). The panel has its own **Undo** and **Redo** buttons too. A slider drag is one step.

**Source changed.** If the source NIF changes on disk (a mod update), the edits are re-applied by name and role, not by position. The panel says "Source changed: N applied, M conflicts". A conflicting edit has **Take source** (drop your edit) and **Keep mine** (keep it on top of the new source).

**In game.** While an edit is open, the toggle reads **In game (simulated)** and **Edited source**; see **Animation** below. Once you have exported, the amber line "PGPatcher output predates your edit: re-run PGPatcher." shows: the game still loads PGPatcher's copy, which was made from the unedited NIF, until you re-run PGPatcher. If the edit preview cannot be shown, the line "Your edit could not be shown. Switch to In game (simulated) or Edited source to retry." says so; edits you make meanwhile still count.

**LE files.** A Skyrim LE NIF opens without a 3D preview ("LE mesh: no 3D preview").

**Not yet.** Splitting a shared shader, or a shared interpolator for a value edit (the edit is refused or is a conflict); an outline for the selected shape.

#### Animation

The edit preview plays the shader and alpha controllers of the NIF you are editing. A NIF shown without **Edit** does not animate.

**Playback.** When the edited NIF has a controller that animates, two rows sit under the 3D view: **Play** (or **Pause**), **Loop** ("Start again at the end"), **Speed** (0.1× to 4×; 1× is game speed), then the **Time** slider in seconds. Moving the slider jumps to that time and pauses. Without Loop, playback stops at the end, and Play starts again from the start. The slider runs from 0 to the end of the longest controller at its frequency (twice as long for a Reverse cycle). Below 30 frames a second the animation slows down instead of skipping. Playback only changes material values, so the mesh is never reloaded. A controller whose times are not numbers gets no controls, only the amber line "This animation has invalid times: playback is off." If you switch to the Textures view, the clock keeps its time and carries on when you come back. **In game (simulated)** pauses the clock and hides these rows; after switching back to **Edited source**, press **Play** again.

**The Controllers tab.** Each shader and alpha property lists its controllers, then **Add controller**. A float, colour or alpha-test controller has:
- A header with its name, its class, "Managed by a clip" when a clip drives it, and **Remove**. Remove unlinks the controller; the BSX Animated bit stays set. It is off for a controller a clip drives ("Driven by a clip: it cannot be removed.").
- **Variable**, **Cycle** (Loop, Reverse, Clamp), **Active**, **Play backwards**, **Frequency**, **Phase**, **Start**, **Stop** and the interpolator's value. You can change the Variable of a controller a clip drives: "Its clips follow the new variable."
- **Interpolation**: Linear or Quadratic. Linear to Quadratic adds tangents that keep the curve's shape; Quadratic to Linear drops them.
- The curve graph: the keys as handles, Quadratic tangent handles, and a cursor at the current time. Drag a key to change its time and value; drag a tangent handle up or down. One drag is one undo step. Click or drag the background to move the preview time. Times are never clamped: a key dragged past its neighbour gives the red error "Key times must not decrease". A curve too large to draw says "These keys are out of range for the graph."; the table still works.
- The key table: Time, Value (R, G and B for a colour), Forward and Backward for Quadratic keys, typed as exact numbers, and **Remove** for each key.
- A colour key also has a **Colour** swatch that opens a colour picker. Each drag in the picker is one undo step; numbers typed in the picker are one step until it closes. Channels you do not change keep their exact values. A key with a value outside 0-1 (a bright emissive colour) gets a greyed swatch: "Values outside 0-1: edit R, G and B directly."
- **Add key**: a new key after the last one, at the last key's time plus the average spacing between the keys (0.1 s with one key), with the last key's value. An empty curve starts at the start time. When no later time is possible (the last key is at the largest number), it is off: "No later time is possible for a new key."
- A controller's **Stop** follows its last key when you edit its keys (drag, table, Add key, Remove, Interpolation), in the same undo step; **Start** moves only when the first key goes before it. A clip's start and stop do not change.

TBC, XYZ and CONST keys are drawn but cannot be edited: "These keys are previewed, not edited." Keys you edit must be Linear or Quadratic, in time order and finite numbers. Otherwise a red error ("Key times must not decrease", "Only linear and quadratic keys can be authored", "Key values must be finite numbers") blocks the NIF's export. A key edit on a curve that another controller or clip shares makes a copy first.

**Add controller.** On a shader property, pick **Float** or **Colour** and the **Variable**. An alpha property adds an alpha-test controller. The new controller has two Linear keys, at 0 and 1 s, that hold the property's current value, so nothing changes until you move a key; it loops at frequency 1. Adding sets the BSX Animated bit (a root without BSXFlags gets one). On the Extra data tab that box stays ticked and locked while a controller outside any clip animates the model. The button is off, with the reason on hover, when the root is not a node or the property cannot be found again in the file. On a shared alpha, Add controller splits it first (one undo step).

**PBR names.** On a PBR shape, as on the Shader tab, glossiness reads **Specular level**, specular strength **Roughness scale**, and specular colour **Coat colour**, **Subsurface colour** or "Specular colour (no effect on PBR)".

**Warnings.** These come from an in-game check of each controller and show under the controller.
- Red: "Env map scale crashes the game on PBR materials." On a PBR shape, Env map scale (8) is greyed in both Variable lists with this text. A controller that already has it blocks the NIF's export, even when the source file had it.
- Amber, from the last In game simulation: on a shape that is not PBR but that PGPatcher makes PBR, an Env map scale controller gets "PGPatcher makes this shape PBR: its Env map scale controller will crash the game." It does not block export, since PGPatcher's output depends on the JSON at play time.
- Amber, no effect in game: "This controller has no effect: Specular is off when the mesh loads." and "…specular strength is 0 when the mesh loads." (glossiness, specular strength or colour on a non-PBR shape); "This controller has no effect: alpha test is off."; "Refraction strength has no visible effect in game."; "Two controllers drive <name>: only the last one plays."

**Clips.** When the file has animation clips, a **Preview** list at the top of the tab picks **Free chains** or one clip. A clip shows alone: the other controllers keep their file value while it plays. Under **Free chains**, a clip named SpecialIdle plays by itself, as in the game, and the Time slider covers it. Any other controller a clip drives holds the first key of the first clip the manager lists for it, as the game does while that clip is not called. When nothing moves (only held values), the preview shows them with no Play or Time controls. Under a controller a clip drives, each clip shows its name, cycle, time span and text keys (one line; hover for all of them). The selected clip's keys get the same graph, table and Add key; the others say "Pick this clip in Preview to see and edit its keys." A clip with several interpolators for one controller cannot be edited ("This clip has several interpolators for this controller: they cannot be edited."). "No clip in this file drives it." marks a controller flagged as managed that no clip uses; it holds its property value.

**Making clips.** These controls sit in one section at the end of the Controllers tab, **Clips (N · showing X)**, closed by default (N clips; X is the clip the Preview shows, or free chains). It opens by itself when a clip action is refused, so the red reason is seen. **Preview** stays at the top of the tab, outside the section. Under each controller a clip drives, one weak line names the clip: "In clip SpecialIdle · Loop · 0 to 2 s". Making a clip needs a node as the file's root ("The root is not a node: a clip needs a node root.").
- **Convert to clips.** One row per property that has controllers ("Convert to clips: shader property"), a name field (it starts as SpecialIdle) and **Convert to clips** move that property's free controllers into one new clip. The clip keeps their keys, uses their shared cycle and frequency, and runs from the earliest start to the latest stop. SpecialIdle loops constantly in game; Open and Close play as door states. The field and the button are off, with the reason on hover, when there is nothing to convert ("This property has no free controllers with keys."), the controllers run on different timings ("These controllers run on different timings: they cannot share one clip."), their cycle is not Loop, Reverse or Clamp ("The cycle must be Loop, Reverse or Clamp."), their time range is empty ("Stop must be after start."), the shape has no name or shares its name with another shape, or the alpha is shared ("This alpha is shared by N shapes: split it before editing."). A refusal found on the click shows in red under the row.
- **New clip.** At the end of the section: a **Name**, a **Cycle** (Loop, Reverse or Clamp; it starts on Clamp), **Start** and **Stop** in seconds (0 and 1 to begin with), and a tick box for each controller to put in the clip. **Add clip** adds it with each ticked controller's keys. A controller whose keys are TBC, XYZ or CONST starts flat instead (hover: "Its keys are not linear or quadratic: the clip starts flat."). The ticks clear when you open another file or select another shape. It is off, with the reason shown, when the name is empty ("Type a name for the clip."), nothing is ticked ("Tick at least one controller."), or Stop is not after Start ("Stop must be after start."). A controller on a shared alpha has a disabled tick box with the split hint.
- **Rename and Remove.** At the top of the section, with a clip picked in **Preview**, the **Clip name** field renames it when you leave the field (Escape cancels), and **Remove clip** deletes it. Each is one undo step, and Enter never removes a clip. Both are off on Free chains ("Pick a clip in Preview to rename or remove it.") and for a clip with no name ("This clip has no name: it cannot be renamed or removed here."). A name must not be empty or repeat another clip's name (any letter case). Removing the last clip returns the Preview to Free chains and frees the controllers it drove. It also takes the now empty clip manager off the root, because the game crashes on a manager with no clips, and the export leaves it out. A file whose own manager has no clips shows "This file has a NiControllerManager with no clips: the game crashes on it." as a warning. Removing the last clip on a controller gives it that clip's keys, so the order of removes decides which keys come back. A key edit made on a clip is refused as a conflict when another clip has since taken its place (after a Revert); the Preview then returns to Free chains rather than show the other clip. When an entry of the root's controller chain cannot be read, adding, renaming and removing clips are refused ("The root's controller chain cannot be read.").
- **Timing.** Under **Remove clip**, the picked clip's **Cycle** (Loop, Reverse or Clamp), **Frequency**, **Start** and **Stop** (seconds) are editable; the Time slider follows them. A change is one undo step ("Set clip timing"), and a drag is one step. Text keys are left as they are. A bad value is not clamped: an amber line says why ("Clip SpecialIdle timing: start is after stop; the clip keeps the timing it had"), and the export writes that clip with its old timing. The checks: the times must be numbers, the cycle Loop, Reverse or Clamp, the frequency not 0, and start not after stop.
- **Split alpha** also works on an alpha a clip drives: both alphas keep following the clip.

**Colour strip.** A colour controller's curve graph has a strip right under it that shows the colour the curve gives at each time. Click or drag it to move the preview time. Where a channel is outside 0-1 (a bright emissive colour) the strip has a dashed band along its top, and that key's swatch has an outline. A float controller has no strip. The strip shows the stored colour, so it can look dimmer than the game, which multiplies it by Emissive Multiple.

**In game (simulated) and Edited source.** While an edit is open, the toggle above the view reads **In game (simulated)** and **Edited source**, and the edit opens on Edited source. In game (simulated) runs Tessalith's PGPatcher simulation on your edited NIF and shows still materials (the clock pauses). PGPatcher's real output, made from the unedited NIF, is not shown while you edit. The line under the toggle, and the toggle's hover, say "Simulated as PGPatcher 2.3.1: loose JSON only, no modrules priority, read at the last scan". The JSON is read in the background ("Reading PGPatcher JSON…") and kept until the next scan or another scan source. A folder scan has no MO2 instance: "In game needs an MO2 instance: no PGPatcher JSON was read." For the selected shape a line says what happened: no JSON matches it, PGPatcher skips it (PG_IGNORE, amber), a file is not applied and why (amber; the next file can still match), it is already PBR, or which keys are not previewed. An amber line says when the shape carries a PG_STOCK block: PGPatcher first reverts such a shape to its recorded stock state, and the preview shows it as loaded. A red line says when PGPatcher 2.3 crashes on a JSON (a match key such as `match_diffuse` or `nif_filter` that is not a string, in any JSON the instance loads): the whole run stops, so every shape stays as edited and shows one red line per such file, including shapes PGPatcher would leave alone (no texture set, PG_IGNORE). The Textures view's 3D set preview shows the same red lines and no patched material. A red line also says when PGPatcher makes the shape PBR while it has an Env map scale controller, which crashes the game.

The simulation does not cover: JSON inside BSAs; PGPatcher's own mod priority (`modrules.json`; the MO2 order stands in); plugin alternate textures (TXST); the plugin and mesh-blocklist rules that decide which meshes PGPatcher patches; complex-material and parallax competition; shapes with no texture set; JSON changed on disk since it was read (rescan). It follows PGPatcher 2.3.1 (it does not simulate the PG_STOCK revert).

## Artist checks

Six checks read the numbers Tessalith already measures while it plans, and tell you about maps that will probably look wrong in game. They only warn. No check blocks or cancels an export, none asks you anything, and none changes "ready": no amber dot on a tile, slot row or set, no "Not ready", and the header **Export** stays as it was. Each has its own switch in **Advanced → Checks** (all on by default, saved in `gui.toml`), and a switch hides its results at once, with no re-plan.

| Check (switch) | What it flags |
|---|---|
| **Value range** | A PBR albedo that is too dark or too bright, a metal that is not black or white, an `_rmaos` with mostly extreme roughness or a dark AO channel, metal that is darker than metal should be, an emissive map that is mostly bright background. Code `CHK-RANGE`. |
| **Plastic look** | A vanilla `_n` with no alpha, or an alpha that is almost all white: the specular is then flat and full. A soft warning, because mesh values vary. On a hair or Advanced Skin set the message adds that Community Shaders does not read that alpha. An `_msn` never raises it. Code `CHK-PLASTIC`. |
| **Low detail** | A texture whose top mip adds almost nothing over mip 1 (an upscale, or a 2K made from a 1K). Measured during Export. Code `CHK-LOW-DETAIL`. See *Half size* below. |
| **Green direction** | A normal map that looks like OpenGL when it is read as DirectX (`CHK-GREEN-GUESS`, an Info result, never an auto-flip) and a normal whose blue channel points the wrong way (`CHK-Z-SIGN`). |
| **Parallax** | A height map (`_p`) or a complex `_m` alpha, judged against the set's neutral height (0.5, or 1.0 with a multilayer coat), that uses too little range, clips, is mostly white, or is steep enough to tear; landscape sets whose displacement scales differ by more than 2x. Codes `CHK-PARALLAX` and `CHK-PARALLAX-SCALE`. |
| **UV coverage** | UV islands that sit closer than 8 texels to each other for more than 2 % of the used texels, so colours bleed across them at a distance (mip 3 and up). Code `CHK-UV-GUTTER`. Needs a Meshes scan; see below. |

**Where the results show.**
- **Problems rows.** Each warning is a row in the bottom panel's Problems tab, after the ordinary warnings, with a grey **check** dot (not amber: a check is not a ready signal, Note FC3). The tab shows a **Checks** pill while any exist; click it to narrow the list to check rows (click again to see everything). With a set filter on, it narrows to that set's check rows and keeps the set.
- **Short normals.** A normal that is far from unit length gets one row, `CHAN-NORMAL-LENGTH`, with a **Rebuild Z** button that sets the file's `channels.reconstruct_z`; it is greyed out with the reason when `sdc.toml` is read-only.
- **Set lines that match no file.** Each line of a set in `sdc-project.toml` that names no file (the card's red **?** chip) is a warning row, "No file matches …", with a **Remove from set** button that takes the line out as one undo step (**Delete set** when none of the set's files is left). It is greyed out with the reason when `sdc-project.toml` is read-only.
- **The ⓘ badge.** A set card shows **ⓘ n** beside its **⚠ n**, in the weak text colour: *n* counts the set's Warning-level results (a plain **ⓘ** means only Info results). Hover it for the list; click it to open Problems on that set.
- **The green-direction guess** is a check row too, with **Treat as OpenGL** as its button (it flips green on that texture, one undo step). It also shows on the badge's hover and in the texture's own settings panel.
- **Never in Review or in the Files rows.** A check never opens Review and is not copied into an export's file rows, so it does not show twice.

**When they run.** Checks are computed from the analysis cache when a plan lands, so they cost no extra load. The set-level ones (dark metal, landscape scale) use the 128-pixel thumbnails of the set's members.

**The end-of-export summary.** When an export ends, one Info line (a toast and a Messages entry) counts the check rows, for example *Checks: 3 warnings on 1 texture and 1 set; see Problems*. It is not a dialog, so an open dialog stays.

**Check all UV coverage.** UV coverage is read only on request. Turn on the preview's **UV coverage** toggle for one texture, or press **Check all UV coverage** in Advanced → Checks for every colour texture of the open folder; a bar shows *done / total* and **Stop checking UV coverage** ends it. It reads the Meshes scan: scan your MO2 instance in the Meshes view first. The toggle is greyed out with the reason while no scan has finished (an empty scan counts as none), while a scan is running ("Wait for the Meshes scan to finish") or was stopped ("The Meshes scan was stopped: scan again to check UV coverage"), for any sub-type but diffuse, PBR albedo and skin albedo, and while a pin is compared. Landscape diffuses are left out, because terrain does not use NIF shapes. Results are kept for the session and cleared when a scan finishes.

**Range overlay.** The preview toolbar's **Range** toggle (after *Tile 3×3*) paints the texels that break the value-range rule in magenta over the Source side, at the mip on show. It is drawn for every texture, as **UV coverage** is, and works only when the open texture has a per-texel `CHK-RANGE` warning (albedo luma, metal grey, extreme roughness or emissive background); the dark-metal and AO-dark warnings are not per-texel, so they leave it greyed out, and the hover says why. Also greyed out with "Hidden while comparing" while a pin is compared. It is not saved, it is not drawn in the lens, and it is built in the background, so a large texture never stalls the window. With **Tile 3×3** the overlay repeats with the picture.

**UV coverage overlay.** The **UV coverage** toggle (after *Range*) darkens every texel that no mesh using the texture covers and leaves the used ones clear, over the Source side (v = 0 at the top, as in the DDS). Hover it for the used share, the number of meshes and the gutter share. When the gutter cannot be measured (4096 pixels or wider on either axis, or until the written size is known) the hover says so and raises no warning.

**Half size.** With **Low detail** on, **Measure whether full size adds anything** (also in Advanced → Checks, greyed until Low detail is on) measures every texture on each export, up-to-date ones too. Export always writes the full texture; nothing is held back. Review then asks about the textures the last export flagged (hover: mip 0 adds little detail over mip 1, `CHK-LOW-DETAIL`).
- Review's Undecided column lists them under **N textures added nothing at full size last export**, one row per texture with a menu: **Half size** or **Full size** (an unanswered row reads *Half or full size? ▾*). The rows count in *Undecided (n)*, and Export waits with "Answer half or full size for N textures" until each has an answer. When `sdc.toml` is marked read-only, **Half size** is greyed (hover: the half-size choice cannot be saved) and **Full size** still works.
- Review's Export saves `drop_top_mip = true` on each texture answered **Half size** (one undo step, *Half size*), waits for the new plan, and exports once: those textures are written from mip 1. **Full size** writes nothing to `sdc.toml`. **Close** and **Esc** write nothing; if the export is refused after the half size was saved (or Review is closed before it starts), that step is undone. There is no dialog after the export.
- An answer is for that export only: a texture answered Full size is measured and asked about again next time. A texture the plan no longer flags (resized, already at half size), or whose source file changed since that export, leaves the list and gets nothing written.
- The first export of a texture always writes it at full size, because nothing has been measured yet.
- Without the switch, Low detail only warns in Problems, and Review asks nothing.
- **Advanced → Half size** sets or clears the same per-file field by hand (a tick box with ↺; greyed with "No mips to drop" when the texture has no mip chain). The CLI honours the saved field, so both write the same bytes.

**Copy settings.** A half size saved on the source texture is a tick in the *Copy settings* list (*Half size: true*), like any other field.

**Toksvig gloss bake (opt-in).** On a `_n` in a set with a complex-material `_m`, setting its *Normal handling* to **Renormalise and bake** (`mips.normal = "renormalize_bake"`) also bakes the normal's variance into that `_m`'s gloss, to cut shimmer at a distance. It is off by default and changes the `_m` bytes only when you choose it.

## The bottom panel

A panel runs along the bottom of the window in both views, full width. Collapsed it is one strip of tab buttons; click a tab to open the panel on it, and click the tab that is showing (or the **▼** at the right) to collapse it. Drag its top edge to resize. The tabs are **Problems (N)**, **Review** (listed only while Review is open), **Messages** and **Files**. The Messages button's number counts notes you have not seen.

**Problems.** One row per thing that needs your attention: blockers first, then undecided textures, then warnings. A coloured dot starts each row: red blocks the export, orange is a warning or a decision to make, grey is a check or an info row. Then come where it is (a texture, set or file you can click; "Project" for a problem that belongs to no file), and a sentence that names the action ("This alpha channel carries data the format would drop — choose what it means"). A row never prints a code (Note FB8): hover the sentence for the engine's own message and the code (`LOSS-ALPHA-DATA`), which is also what Troubleshooting and the `--allow` lists use. A problem with no sentence of its own shows the engine's message. A row is one line and does not wrap: the fix buttons sit at the panel's right edge and stay visible, and a sentence too long for the room left ends in an ellipsis. Each entry of the **Decide…** menu (Remove, Cutout, Blend, Cutout + Blend, Data) has a hover that says what it does; the same lines are on the alpha buttons in Review and in a texture's settings. The rows are:

- Blockers the export would stop on, for example a set that matches nothing.
- *Failed: …* for a texture that failed to plan.
- *Undecided: sub-type; what its alpha means; <the warning's sentence>* for an undecided texture (a question that is an acknowledgement shows the sentence of its warning, for example "This texture's size isn't a power of two — resize it or acknowledge"; its code is on the hover), with the fix in the row: the suggested type as one button, **Set type: subsurface tint ✓** (a click decides it), with **▾** beside it for the type picker, or a plain **Set type…** that opens the picker when there is no suggestion; **Decide…** (the alpha choices) and **Acknowledge**. The type picker opens at its button: the suggestion first, marked *(suggested)*, a search box that has the keyboard (type `tint` to list only the types with "tint" in their name), and the grouped list below it, which scrolls; Esc closes it and does nothing else. **Accept all suggestions (n)** at the top of the list decides every texture that has a suggestion, as one undo step. A row takes the keyboard (Tab, or Shift+Tab back): **Enter** or **Space** on a row with a suggestion accepts it and moves to the next row; on the last row the keyboard stays on the list. A row without a suggestion ignores both. Every accept edits the project in memory, like any other edit: **Save** writes it to `sdc.toml`. These buttons are greyed out, with the reason on hover, while `sdc.toml` is read-only ("Wait for the plan to finish" while a plan runs).
- Export pitfalls, texture and set warnings, with **Go to set** on a set's row.
- Artist-check warnings (see Artist checks), after the other warnings, with a grey **check** dot that does not change "ready". A **Checks** pill narrows the list to them.
- Info rows last, with a grey **info** dot: they never count against "ready" (the tab's number counts every row shown, these included). Each is something Tessalith changed for you that you may want back, with **Undo this change** while that step is still the last one: a packing fill dropped because a helper now fills the channel, and a format or tag reset when a texture's type changed. A `_curves`, `_curvature` or `_cavity` map no recipe reads is an info row too, with no button: "Read only by Also export; not written on its own".

**Every row you must act on has its action as its button (Note FC3).** A row never just reports: *No file matches …* has **Remove from set** (or **Delete set**); a stale generated map (`GEN-STALE`, a warning row on that map) has **Regenerate…**, which opens the generate dialog with that map ticked and writes nothing until you press Generate there; a short normal has **Rebuild Z** (greyed with "Rebuild Z is on for this file: export again to rewrite it" once it is set); a folder that could not be read is a Project row with **Open folder**; the Vanilla/CM derive results ("no envmap", "NIF suggests …") have **Open report** (or **Show in Messages** when no report was written); an unclear cubemap layout has **Set layout ▾**; a PGPatcher feature clash has **Turn {feature} off**; a PGPatcher path error has **Fix path**, which selects the set and puts the keyboard in that field (a `rename` or match path; a slot path error has **Go to set** instead, because slot paths are edited in the JSON editor); a set row keeps **Go to set** beside its fix; and a NIF problem from the Meshes view has **Open the {tab} tab**, with the edit panel's own tab name (*Shader*, *Alpha*, *Controllers*, *Extra data*). These buttons only act on their own click: Enter never runs them, and they are greyed while a plan runs or while the file they write is read-only.
- A file's export warnings, once the export has ended. Click the file to select it.

**Remedies that used to be done by hand are buttons too (Note FC10).**
- *sdc-project.toml cannot be read: TOML parse error at line n…* is a red Project row (the parser's whole message on hover) with **Open in editor**, which opens the file with Windows' default program for it, and **Reload**, which reads both files again (it asks first when something is unsaved). Sets and the JSON stay read-only until the file is fixed, and the banner still says why.
- *sdc.toml is read-only: changes cannot be saved* (or `sdc-project.toml`) appears when a save is refused because the file has Windows' read-only flag; the save no longer raises an error dialog. **Clear read-only flag** clears it on that file only. With nothing unsaved the files are then reloaded; with unsaved edits they are kept, and the status line says to Save.
- *also.json cannot be read* (the Also export's record, `<PBR folder>\_sdc\also.json`) has **Reset also.json**, outlined in red: it deletes that file only, and Enter or Space on it does nothing. The manifests do not list the report, zips or sums file, so nothing rebuilds the record: the next Also export writes a new one, and each report, zip or sums file already there counts as one Tessalith did not write. That export keeps each one and says so; delete them to have them written again.
- *Preset {id} was skipped: it clashes with {other} on aliases* is a user preset skipped because another preset, which loaded first, already declares its suffix aliases (for example a copy made by hand, or by an `sdc presets export` older than Note FC10; exports now leave the aliases out). Files load in name order, so the skipped one can be the original: `mine-export.toml` loads before `mine.toml`. **Remove aliases from {id}** deletes the `[suffix_aliases]` table of the skipped preset's file (its hover names the file), keeping its comments and other keys, and plans again so the preset loads. It is greyed while an export runs. It and **Clear read-only flag** answer a click only, not Enter or Space.
- Info rows: *Looks like complex grass, but is not tagged as grass* (a diffuse that has the 1:2 complex grass shape, with a normal-map bottom half, that no grass record of a scan names) has **Tag as grass**, which writes `subtype = "complex_grass"` for it; *Colour divided by alpha on load (premultiplied EXR)* (an OpenEXR source with partial alpha) has **Straight alpha**, which writes `alpha.exr_straight = true`; *matchN is empty and matches nothing* (a set's stored `matchN = ""`, N from 2) has **Remove match**, which removes the key.
- The sub-type picker and the sub-type lists (the texture's Undecided box and Review's undecided rows) offer **Complex grass** where the set's shader is a grass shader or no `textures` folder is above the file (there the scan's grass records can never tag it). An OpenEXR source's settings have **Straight alpha** in the Alpha group.

A click on a texture, set or file switches to the Textures view and selects it. The list opens narrowed when you arrive from a count: **N undecided** at the foot of the Textures column (*Undecided only ×*), a set's **⚠** badge, or the set editor's "N problems in this set — Show in Problems" line (*Set: name ×*). Click the chip to see everything. That one line replaces the set editor's old Warnings block with its raw codes.

A green dot marks what is ready: a texture tile or a set with nothing to decide. The header **Export** has no dot: it reads "Review n files" in the plain button colour until the project is clean (a folder chosen, files to write, planning finished, nothing undecided), then "Export n files" in the accent colour. With no folder open it reads plain "Export". Hover **Export** for "N files, M problems" and what Review still has open.

**Review.** Press **Export**: a clean project exports at once, but when something is blocked, undecided or worth a second look, Review opens in the panel instead of a dialog. It opens for any of these: a blocker, an undecided texture, an export pitfall, a half-size question (see Artist checks), a PGPatcher JSON edited outside Tessalith, or NIF edits waiting to be exported (Review's **Export** is the only way they are written). When Export becomes available, the button (in Review and in the header) fades to the accent colour over 0.15 s, and the header's "Review n files" turns into "Export n files"; losing it snaps back at once. Review does not lock the window. Keep editing and its lists update; Export from Review always uses the plan current at that moment. Review never exports by itself, not even when you decide the last texture: its **Export** button is the only way out. Enter does nothing there.

- Each column's heading carries its count: **Blockers (n)**, **Undecided (n)**, **Warnings (n)**. A missing export folder is a blocker, so it counts.
- **Size and narrow windows.** Review opens at 40 % of the window's height; drag its top edge to change that, and Tessalith remembers your height for Review. Under 1200 points of window width the sections stack in one scrolling column (Blockers, Undecided, Warnings, then Also export as when it shows) instead of sitting side by side. Review and Problems keep separate heights, so the tab strip moves when you switch between them, and the 40 % is worked out once, when Review first opens.
- **Blockers** (red), with **Go to set**. Export stays greyed out, with the reason beside it ("Fix 2 blockers first"), until they are fixed.
- **Undecided**: one row per texture with its question: a sub-type box and **✓**, the alpha choices, or **Acknowledge for this texture**. Click the name to select the texture. **Accept all suggestions** decides every texture that has a suggestion, as one undo step; the others stay listed. A texture decided here leaves the list. Below them, the half-size rows: **Half size** or **Full size** for each texture the last export flagged; Export waits ("Answer half or full size for 2 textures") until each is answered, and writes the Half size answers to `sdc.toml` when you press it.
- **Warnings** (what re-encodes after an upgrade, then pitfalls grouped by set): after a Tessalith upgrade, one row per reason files re-encode (`2 files re-encode: the normal encoder changed in 1.1.0`, `their settings changed`, `new output type`), compared with what the older version recorded. An export folder with no manifest shows a plain line, `First export with 1.1.0: 20 files`, that asks nothing. The rows go when the export starts. Tick each one to say you have seen it, or press **Acknowledge all**. Export stays greyed out ("Acknowledge 2 warnings first") until every current pitfall is ticked. Ticks count for this export only: they are not saved, they go when the export starts or Review closes, and a changed or new pitfall needs a new tick. With no pitfall to tick the column reads "None that block the export"; "N warnings in Problems (do not block)" opens the rest.
- **What will be written**: the number of DDS files and one line per JSON file with its state on disk: *will be written*, *will be replaced (written by Tessalith)*, *edited outside Tessalith* or *cannot be read; kept*. Above them, at the top of the footer, **NIF edits (n)** lists each NIF with pending edits: `path · mod · n unused blocks removed · written to <export folder>`. A NIF edit that cannot be exported is a warning instead: "NIF edit skipped: <reason>" in amber in the Warnings column, counted in its number; it never holds back the textures. The NIF edits are written once the texture export (and, with Also on, its zips) has ended; a cancelled export writes none. The result is a line in Messages and in the export notes.
- **Stale outputs (n)** (Note FC11), under the NIF edits: the files an earlier export wrote into the export folder that this project no longer writes, from its manifest. That covers a renamed set's old files, a skin set's old `_f.dds` or its old files under `textures\pbr\`, the old `_rmaos.dds` after a recipe switch, and the output of a source you deleted. Each row is `path · no longer written` (or `· its source is gone`). A file that still has the size and time Tessalith recorded when it wrote it has **Delete** (red outline); a file changed since, or one written before Tessalith recorded those, reads `edited since Tessalith wrote it: left alone` and has no button. **Delete** acts on a mouse click only, never on Enter or Space, never on Export, and not while an export runs; it checks the file again when you click, and a file changed in the meantime is left alone. Old JSON files Tessalith wrote are listed too (a PGPatcher JSON under an earlier name, a Community Shaders PBR JSON no block binds, a complex-material JSON no set writes): one still matching the hash Tessalith recorded has **Delete**, an edited one is left alone. The rows never block Export, ask nothing and do not open Review by themselves; while any has **Delete**, Problems shows the Info row "*n* old outputs Tessalith wrote are no longer exported" with **Review…**, which opens Review.
- **Overwrite questions** (in Blockers): a PGPatcher JSON edited outside Tessalith ("<name> was edited outside Tessalith") and a NIF whose export path holds a file Tessalith did not write ("<path> was not written by Tessalith") each have **Keep the edited file** or **Overwrite it**; neither is chosen until you click, and Review's **Export** stays off ("Answer Keep or Overwrite for <name>") until every one is answered. The answer is tied to the file as it is now: a change to the file before you press Export is asked again; a change during the export is kept, with a note. The answer applies to the next export only; closing Review or a reload clears it. The Community Shaders PBR and complex-material JSON show their state only; a file of those edited outside Tessalith is kept, with a note, as before.
- **Export 20 files (skip 2 undecided)** exports the decided textures and skips the rest; it never decides for you. **Close** closes Review and cancels an Export it had queued.

If a source changed on disk or a plan is still running, a click on Export waits for the plan and then checks again; a new pitfall in the meantime stops the export and says why in Review. Opening another folder or reloading closes Review and exports nothing. If the plan fails, Review stays open with its blockers.

**Messages.** The last 500 entries, newest first, with the time, the severity and the text; **Clear** empties the list. **Ctrl+M**, or a click on the **Messages** tab, opens this tab, or collapses the panel when it is already showing it. Toasts appear at the bottom right, just above the panel while it is open, so they never cover its buttons (Review's Export included; Note FC8).

**Files.** The export's progress, counts and files (see Export).

## Export

**Export** converts the folder into the export folder (**Export to ▾** in the header; which is not drawn until you choose one). It cannot write into the folder it reads, and Review blocks the export until a folder is chosen ("No export folder chosen"). The export folder belongs to the project: the one you pick is saved as `[project] export_folder` in that folder's `sdc-project.toml` (at once, or with the next Save while the file has unsaved edits), so opening another project does not send its textures into this one's folder. A project that has none has no export folder yet: the `gui.toml` value older versions saved for every project is no longer inherited (it is only where the folder dialog opens). Without a usable `sdc-project.toml` (one that does not parse) the pick goes to `gui.toml` as before.

- If something is blocked, undecided or worth a second look (a pitfall, or a PGPatcher JSON edited outside Tessalith), **Review** opens in the bottom panel instead of exporting. Its **Export** button is the old *Proceed anyway*: it exports only the decided textures and skips the rest, and it never decides for you. See [The bottom panel](#the-bottom-panel).
- If a source file changed on disk since it was planned, the textures concerned show "changed on disk" and the Textures column offers **Reload**. Reload plans again, re-reading only the changed files. Export checks first and plans again by itself, so the export uses current files. The GUI also checks whenever its window regains focus.
- The **Files** tab of the bottom panel opens when Export starts. While the export runs its line reads *done/total · elapsed · files/s · ETA* (the bar glides to each new count over 0.3 s; the text is the exact count): files per second is the average of the last 10 seconds, and the ETA appears once 3 files have finished or 2 seconds have passed. **Cancel** stops the batch; **Save report…** writes the report in the background and says "Saved report: <path>" (or why it failed) in the status line and a toast; **Copy CLI command** copies the matching `sdc` command; **Open export folder** opens the export folder in Explorer (greyed out, with the reason, until Export has created it); **Close** collapses the panel. What the export did besides converting (a JSON written, not written or kept, the borrowed-slot copies, files left in place) is listed under **Notes**, a collapsible list that scrolls when it is long; the Markdown report has the same lines under *Notes* (the JSON Lines report stays the engine's event stream). The hash of each JSON Tessalith writes is recorded at once in `_sdc/generated.json` beside `sdc-project.toml` (Note FC11), so discarding unsaved edits after an export, a crash, or a read-only `sdc-project.toml` no longer makes the next export ask about Tessalith's own JSON.
  - The *Files* tab lists each file with its state and handles thousands of files: only the rows on screen are drawn. **Failed only** (failed, or failed validation) and **Has warnings** narrow it, and together they show the files that match both. Click a row to select that texture. **Show in Explorer** on a row selects the written output once it exists, otherwise the source file.
  - There is no Warnings tab any more. A file's export warnings show when you hover its row, and the **Problems** tab lists them, once the export has ended, as rows that select the file.
- **Also export as Vanilla / CM** (`[export] also` in `sdc.toml`): while a tick is on, Export always opens Review, and Review's Export writes three folders side by side in the Also export location (`[project] also_location` in `sdc-project.toml`, by default the export folder): `<project> PBR` (today's export, with the PGPatcher, CS PBR and complex-material JSON), `<project> Vanilla` and `<project> CM`. Files rows of the Vanilla and CM folders start with the folder name. **Copy CLI command** then passes the location as `-o`. **Open export folder**, the header's export path, the DDS header patch and the JSON editor stay on the export folder; by default the location is that folder, so it shows the three folders. See [Also export as Vanilla and CM](#also-export-as-vanilla-and-cm).
- When Export ends, one Info line counts the artist-check warnings ("Checks: 3 warnings on 1 texture and 1 set; see Problems"). With **Measure whether full size adds anything** on, the textures it flagged are asked about in Review before the next export (see Artist checks).
- **Copy CLI command** copies the `sdc convert` command that reproduces this export from the command line (same folder, output, BC1 decoder and thread count, and `--accept-suggestions high`, as the GUI plans; an NVTT path chosen in Advanced is not included: add `--nvtt <path>`). Because Export saved `sdc.toml` first, that command gives the same manifest records and the same DDS bytes for everything `sdc.toml` decides. It does not carry the set edits in `sdc-project.toml` (moved files, set renames, output names, set shaders) or the mesh and grass evidence from the scan: the CLI reads neither, so sets that depend on them come out differently. The sub-types and alpha meanings that evidence decided are in `sdc.toml`, so those carry over.

### Also export as Vanilla and CM

One export can also write a vanilla version and a complex-material version of a PBR mod. It needs the cs mode: the PBR folder is the cs export.

- **Where to switch it on.** **Export to ▾** (**More ▾** until a folder is chosen) has two checkable items, **Also export as Vanilla** and **Also export as Complex material**; the menu stays open on a tick and there is no dialog. Without a folder open they are greyed out with "Open a folder first". Review has an **Also export as** column with the same two ticks. The column shows in the cs mode or while a tick is on; its red reason line (why Export cannot run yet) shows only while a tick is on. Review's columns draw a thin scroll bar, and the Also column usually needs it.
- **The three folders.** While a tick is on, Export always opens Review, and Review's Export writes `<project> PBR`, `<project> Vanilla` and `<project> CM` side by side (`<project>` is the opened folder's name). Ticking only CM writes the Vanilla folder too: CM installs on top of it. Review's column holds the **Export location** (**Choose…**; it is per project, `[project] also_location` in `sdc-project.toml`, by default the export folder), the three folder names (empty = the default name shown as the hint), **Keep metal brightness** and its **Strength** (CM only), **Also write a zip of each folder** and **Skip these sets**.
- **Installing.** Install either the PBR folder or the Vanilla folder. For complex material install the CM folder on top of the Vanilla folder. With Keep metal brightness off the CM folder holds only the `_m` files (plus the complex-grass stack of each PBR grass set); with it on it also holds diffuses that keep the metals' brightness.
- **What each folder holds.** PBR is the plain cs export, byte for byte, with its PGPatcher, CS PBR and complex-material JSON. Vanilla holds, for each PBR set, a converted diffuse, a `_n` with the specular mask in its alpha, and an env `_m` where the meshes need one; every other texture is copied from the PBR folder when it would come out the same, otherwise encoded. A PBR Landscape set's `_p` is also written to the Vanilla folder (for Terrain Helper). CM holds a complex-material `_m` per PBR set (R metal × gloss, G gloss, B metal, A height).
- **The env `_m` needs a scan.** It is written only for sets whose meshes use the environment-map shader, which Tessalith learns from the Meshes scan. Without a scan no env `_m` is written and the report says "no: no scan". The command line reads no scan, so it never writes one.
- **NIF edits follow the PBR folder** while a tick is on, so one mod folder holds the textures and the meshes, as a plain export does.
- **Skipping a set.** A PBR set can be left out of Vanilla and CM: tick it in Review's **Skip these sets**, or, in 2D, use **Skip vanilla/CM for this set** in the set editor's Material tab (its **Also export** group, shown while a tick is on, reads "converted" or "skipped"). Skipped sets are `[export] skip` in `sdc.toml`. A PBR set with a map still undecided (or blocked by a code you have not acknowledged) is not exported to the PBR folder, so Vanilla and CM leave it out too; the report and the export notes say "not derived: N maps undecided in the PBR export".
- **The recipe.** **Also export recipe** in Advanced (it starts closed; Review's **Recipe settings are in Advanced** opens it) has one box per `[export.legacy]` value: diffuse brightness, AO strength (objects and landscape), curves opacity, metal darkening, specular scale, specular boost at full metal, landscape spec factor and dielectric env. The values and what they do are in the wiki's Project Config page.
- **`_curves` and cavity maps.** A file named `*_curves` or `*_curvature` (a curvature map, 0.5 = flat) or `*_cavity` joins its PBR set and is read only by Also export: it shades the Vanilla diffuse (curves as a soft light, cavity as a multiply, both at the curves opacity). In a plain export it writes nothing.
- **Report and zips.** Every Also export (not a dry run) writes `<project> conversion-report.md` next to the three folders: the counts per folder, the recipe settings, a row per PBR set (suggested NIF Glossiness, Specular Strength, whether the Environment Map shader is needed and the env `_m` was written), the sets not converted and why, and the install lines. With the zip on, each folder that ran becomes `<folder>.zip`, with a line per zip in `<project> SHA256SUMS.txt`. A zip the ZIP format cannot hold (65,535 files or more, or 4 GiB, counted from the planned outputs' sizes) is a Review blocker before anything is written: "Zip too large for the ZIP format (n files, size); untick "Also write a zip" or split the export" (Note FC12). The zips and the report are written after the PGPatcher, CS PBR and complex-material JSON, so the PBR zip holds the JSON this export wrote; the export stays running (and can be cancelled) until they are done. Files Tessalith did not write are never overwritten. Tessalith never deletes either: a file in one of the folders that this export did not write (an earlier export's CM diffuse after Keep metal brightness was turned off, the outputs of a set now skipped) stays, and the report and the export notes list it as "not written by this export" (with the zip on, "not zipped"). Delete such files yourself: a stale CM file overrides the Vanilla file of the same name. To start from scratch, delete the three folders, the report, the zips and the sums file together: their record is in the PBR folder (`_sdc/also.json`), so deleting only the PBR folder leaves the report, zips and sums kept as files Tessalith did not write.

## Messages and toasts

Routine results show as **toasts**: short notices at the bottom right (above the bottom panel while it is open) that do not block anything. *Saved*, *Export finished: N written, M skipped, K failed*, *Scan finished: …*, *Copied 3D view*, *Picker result ignored* and the *Undid / Redid* note each appear as one. A new toast fades in over 0.2 s while rising a few points; it fades out over 0.2 s after 4 seconds (8 seconds for a warning); at most 3 are on screen and the rest wait their turn. The whole toast fades, box and shadow with the text. Holding the pointer over a toast keeps it; a toast you let go of in its last 0.2 s may vanish a little early. With *Reduce motion* on there is no rise and the fades take about an eighth of a second. Anything that needs a decision (Replace or Cancel, an external change, an error that blocks) stays a dialog.

The **Messages** tab of the bottom panel (**Ctrl+M**; the tab's label counts the entries you have not seen yet) opens the Messages tab, or collapses the panel when it already shows Messages: the last 500 entries, newest first, with the time, the severity and the text. Every note that shows in the status line (the encoding-follows-type note, *Export cancelled*, *Picker result ignored*) is also logged here, as are the toasts. **Clear** empties the list. The log lives in memory only; it is gone when you close the window.

## Presets

**Presets…** (the last entry of the Preset combo in the header, or *Open the preset creator* in the command palette) opens the preset creator as a tab of the centre column. While Presets or the JSON editor is docked there, a row of tabs over the centre (**Selection**, **Presets**, **TruePBR JSON**) picks what the centre shows; clicking a texture or set (also the one already selected), or expanding a preview, brings **Selection** back to the front. While one of those tabs is in front the **Advanced** drawer is hidden (it comes back with **Selection**), and the grid and Sets keys wait too, so a key does not change the selection from under the tab. On the view's heading row, **Pop out** shows it in a window of its own (for a second monitor), **Dock** puts it back in the centre, and **Close** closes it, as does closing its window. Opened from the Meshes view, a docked view switches to the Textures view, which has the centre column. Nothing about it is saved in `gui.toml`. It edits your own presets, the files in `%APPDATA%\sdc\presets\` that the command line also loads.

- **The top bar.** Pick a preset. The built-in ones are read-only and show no error; of the editing buttons they offer only **Duplicate**, which makes an editable copy (named `<id>-copy`, without the original's suffix aliases); **New** starts an empty preset on the current target's quality preset. **Name** is the preset's id and file name (lower-case letters, digits and `-`); **Base** is the preset it builds on; **Target** is cs, vanilla, or "from the base". **Save preset**, **Revert**, **Reset preset** (drops every per-sub-type and suffix-branch change, so the base shows through) and **Delete…** (after a confirmation) are for your own presets only. The line beside them says whether the preset loads, or why not, in the engine's own words. **TOML preview** shows exactly what Save writes. If the preset's file changed on disk since you picked it (you edited it by hand), Save does not write: it asks **Overwrite** (write your version over the file), **Reload** (drop your changes and load the file) or **Cancel**. If the file was deleted or no longer loads, Reload keeps your edits and says so; Overwrite then writes them back to the same file. Picking another preset, New or Duplicate while you have unsaved changes asks first. Preset files in the folder that did not load are listed at the top of the view with the reason, and **Open folder** opens the folder.
- **The sub-types.** One row per sub-type, in two families: **PBR / Community Shaders** (the sub-types only the cs target has: PBR, coat, Advanced skin, flow, HDR sky; and complex grass), then **Vanilla** (everything vanilla also has, including glow, envmask and complex_material). Complex grass is under PBR / Community Shaders: both targets have it, but it is a Community Shaders feature. Inside a family the rows are grouped Colour, Normal, Data and Special, where it has them. A row's title shows its format; open it for:
  - **Suffixes**: one branch per suffix that names the sub-type: the built-in suffixes, then your aliases for them (`_bumpy` for `_n`, say). The row's own settings below are the "no suffix" default; a branch changes them for the files with that suffix only. Open a branch (its title shows its format and how many fields it overrides, e.g. `_d — BC7 · sRGB (overrides 2)`) for the same Compression, Resize & mips, Alpha, Channel remap and Packing fills as the row, each hinting what the files get without the branch ("inherits"), with **↺** to drop the change. The title's format is what a file with that suffix gets from the whole preset, its other rules and, for an alias, the canonical suffix's branch included; "(+ rules by alpha)" marks a branch that a rule on alpha content may also change. A branch with no changes writes nothing. A branch is saved as one rule: `match = { suffix = "d", subtypes = ["diffuse"] }` for a built-in suffix, `match = { glob = "*_<alias>.*", subtypes = [...] }` for an alias. Every matching rule applies, in order, each changing only the fields it sets, so branches are written after your other rules (built-in suffixes, then aliases): a branch changes only its own fields on top of them, and an alias branch adds to its canonical suffix's branch. Rules the creator did not write are listed under **Other rules** (read-only) and kept as they are. A `[files]` value or `--set` still beats a branch. **Add alias** adds the alias and opens its empty branch; **Remove alias** removes it with its branch. The rmaos row shows the built-in ORM → RMAOS packing as a read-only `_orm` branch (it needs no preset). A new alias is checked as you type, with the engine's message when it is refused (not lower-case letters and digits, a built-in suffix, an exporter term such as `orm`, or an alias another preset already declares).
  - **Compression**: format (only the formats and tags the engine allows for the sub-type and target), encoder and effort.
  - **Resize & mips**: resize, mip levels, mip filter, and coverage for the cutout policies.
  - **Alpha**: policy, and the threshold for cutout; shown where the format keeps alpha.
  - **Channel remap** (data sub-types): the channel swizzle, the source of R, G, B and A (r, g, b, a, 0 or 1), saved as `channels.swizzle`. A remap for an alias's files is the Channel remap of that alias's branch.
  - **Packing fills** (data sub-types): the values for packed channels without a source map (roughness, metallic, AO, specular, height, 0-255).
- Each field shows the base's value as a hint (in a branch, the sub-type's). A field you changed has **↺**, which removes your change. A sub-type's category, colour space and the other built-in rules are never offered.
- **Saving.** The preset is loaded through the same loader as the presets folder before the file is written; a preset that would not load is never written. Your preset goes back to its own file, edited in place so its comments and layout stay; a new one goes to `<name>.toml`. After a save the folder is read again, the preset is listed in the header's **Preset** menu and the folder is planned again, without a restart. If `sdc.toml` names a preset that has since been deleted, the folder is still planned with the fallback (your config's preset, else the Mode's default) so the window is not empty, but the export is blocked: Problems shows a red row "Preset <id> is not installed" with **Choose preset…**, which opens the header's **Preset** menu. `sdc convert` stops on the same file with exit code 2.
